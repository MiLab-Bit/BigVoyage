## 刀 1 · 构筑深度终稿

### 1.1 支柱修辞（替换旧句）

| 旧（作废） | 新（生效） |
|---|---|
| 「构筑即核心系统」（暗含满编/体系链） | 「**出航前构筑 = COST 分配深度 + UR 情境选择**」 |
| 深度 = 上满 5 / 凑体系链 | 深度 = **同一 COST 预算下的结构取舍** + **按敌情换 UR** |

与支柱 1 对齐：全部策略仍在出航前；本刀只定义「构筑好」的**可测含义**。

### 1.2 玩家可感知的决策（设计意图）

1. **COST 分配**：`4+4+2` / `4+3+2+1` / `4+3+3` / `3+3+2+1+1` 等合法切分，应对不同守卫节奏（速杀 / 持久 / 控场）。  
2. **UR 情境选择**：同一 COST 槽位，换 UR 应改变「打哪类岛更优」——禁止「一张 UR 通吃 12 岛」。  
3. **槽位/同体系**：软上限，防极端；**不**用激励工程强迫打满。

### 1.3 验收判据（设计侧 · 可仿真）

| ID | 判据 | 阈值 | 备注 |
|---|---|---|---|
| **AC-C1** | 固定总 COST=10、仅改变切分结构（至少 3 种合法结构），对 **≥3 个不同主体系守卫** 的胜率排序**不完全相同** | 结构×守卫 矩阵存在交叉 | 证明「分配有情境」 |
| **AC-C2** | 单 UR 槽位轮换（其余槽位最优填充）：**最优 UR 随守卫主体系变化**，同一 UR 不得在 12 岛全胜为最优 | 最优 UR 覆盖 ≥3 张不同 UR | 替换探针②「12/12 全祝融」 |
| **AC-C3** | 禁止再用「满编张数中位数」「体系链占比」作为构筑深度门禁 | — | [B6] 激励工程永久停 |

> 仿真前置：刀 2 独占机制 + 刀 3 技能/克制信号合入参考引擎后复跑；**未合入前 AC-C1/C2 为设计门禁，不得宣称已实测通过**。

### 1.4 明确不作

- 不满编惩罚、满编共鸣、体系链 atk%（§9.3/§9.4 全部终止）。  
- 把「上满 5」写回支柱或 Playtest 硬门。

## 刀 2 · UR 欲望终稿

### 2.1 已决：采纳 R1 四独占（机制非数值）

权威机制表以 `数据层/data-spec/r1_ur_exclusive_effect.md §2` 为准，本处冻结为**合入规格**：

| UR | 独占钩子（别的卡永无） | 欲望叙事（给玩家/NFT） |
|---|---|---|
| `TIDE_UR_01` 波塞冬·深渊之主 | **渊盾拦截 DoT**（盾优先吃 DoT；盾量 `baseAtk×1.8` 独占放宽） | 「只有他能扛焚海」 |
| `IRON_UR_01` 霜铁之王 | **破甲光环**（敌方 effectiveArmor −30%） | 「只有他能撕开铁壁外的甲」 |
| `WIND_UR_01` 追风之翼 | **真伤段**（多段中 ≥1 段无视护甲/`DEF_COEF`） | 「只有他能钉穿要塞」 |
| `FLAME_UR_01` 祝融之裔 | **焚尽**（DoT 不可被盾吸收 + 盾破 50% 溢出） | 「只有他烧穿渊盾」 |

**商业口径（已决）**：UR 溢价 = **机制独占 + 情境不可替代**，禁止用「纯输出 η ≥ 同体系均值」作为上架条件（η 表仅作监控，不作欲望证成）。

### 2.2 与「烈焰主导」脱钩

维持 `r1_balance_verification.md` / `r1_dominance_diagnostic.md`：无全局烈焰主导；R1 **不为重平衡服务**，只服务 UR 欲望与刀 1 的 AC-C2。

### 2.3 验收判据（欲望可测）

| ID | 判据 | 阈值 |
|---|---|---|
| **AC-U1** | 每张 UR 具备上表独占钩子；卡面/图鉴必须写清「独占」二字与钩子名 | 4/4 |
| **AC-U2** | 对每张 UR：存在 ≥2 岛，使「该 UR → 同体系最佳非 UR」替换后胜率下降 | **≥ +8pp**（UR 侧优势） |
| **AC-U3** | 12 岛最优单 UR **不得唯一**；至少 3 张不同 UR 各至少在 1 岛上为最优 | 打破「祝融通吃」 |
| **AC-U4** | gacha/NFT 文案只许强调独占钩子与情境，不许写「UR 面板最强」 | 文案审 |

### 2.4 实装与冻结

- 设计：**已决，可进工程**。  
- 工程合入后：破甲光环 / 焚尽等属战斗常量级 → **必须重冻 `ruleset_hash`**（单次批次，禁止拆两次）。  
- Demo：可用「演示开关」先开 4 钩子做 AC-U2/U3 仿真；未开前不得对玩家宣称 UR 欲望闭环已验证。

## 刀 3 · 克制环可读终稿

### 3.1 诊断（文档层）

探针④「全烈焰 vs 混合 = +0.0pp」在**技能空转 / 仅总量结算**的引擎上必然出现——不是环定义错，是**支柱 2 的可感知通道没进结算与 UI**。

### 3.2 设计修订（三通道同时开）

| 通道 | 规格 | 归属 |
|---|---|---|
| **A 结算** | `armor` / `shield` / `control` / `buff` 按 `GDD-03 §4.7` **必须产生日志条目与数值后果**（Demo Must） | 工程合入设计已有规格 |
| **B 对抗差** | 对「主体系=X」的守卫，**克制方主力编队** vs **被克方同 COST 编队**胜率差 | 见 AC-R2 |
| **C 可读** | 战报：克制高亮、被克标注、结束页「克制贡献伤害占比」；编队页：预测仪表盘显示对当前岛 `+RESTRAINT / −RESTRAINT` | `GDD-03 §5` 升为 Must |

**协同钩子（纸面咬合，非满编激励）**：

- 火墙（烈焰+铁壁同队）：铁壁承伤时，烈焰对**当前锁定目标** DoT 跳数 +0（不改冻结 DoT 公式）——改为 **已有 synergy 文案进日志「火墙」标签**，数值后果依赖 armor 让烈焰存活输出窗口变长（间接）。  
- 锁定爆发（疾风+潮汐）：control 命中后，下一窗口疾风多段对受控目标 **段衰减从该段起按 SEG_DECAY 正常**，日志打「锁定」——不新增冻结常量。  
- **禁止**再引入体系纯度 atk%。

### 3.3 验收判据

| ID | 判据 | 阈值 |
|---|---|---|
| **AC-R1** | 克制环有效性指数（双靶） | **≥ 1.00**（维持既有） |
| **AC-R2** | 对抗差：对 FR 主体系守卫，克制主力队胜率 − 被克主力队胜率 | **≥ +8pp**（技能开启后） |
| **AC-R3** | 混合守卫库上：遵守克制的混合队 vs 同 COST 单体系队 | **≥ +5pp**（替代探针④零信号） |
| **AC-R4** | Playtest：战后能口述「因为克制/被克」为主要原因的比例 | **≥ 60%**（EV-2） |
| **AC-R5** | 战报结束页展示克制相关条目 | 100% 场次可见 |

### 3.4 与段数修正案 C

`GDD-03 §6` 疾风段数修正案 C **保持已决方向**——克制环数学不被段数乘子打穿，是 AC-R1 的前置，不另开刀。

## 4. 支柱条文修订（生效文本）

写入 `00-MDA-支柱-范围分层.md` 的权威句：

**支柱 1（补充验收轴）**  
出航前构筑的深度验收 = **COST 分配（AC-C1）+ UR 情境选择（AC-C2）**；满编/体系链激励不作验收。

**支柱 2（补充可感知门）**  
反制即协同必须同时满足 **结算后果（技能）+ 对抗差（AC-R2/R3）+ 战报可读（AC-R4/R5）**；仅有环定义而无信号 = 支柱未落地。

**支柱 2′ · UR 欲望（附属商业支柱，非 MDA 第四柱）**  
稀缺角色的欲望来自 **独占机制 + 情境不可替代（AC-U1–U4）**，不来自面板 η。
