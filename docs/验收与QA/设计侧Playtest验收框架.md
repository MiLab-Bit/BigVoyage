系统代码：

## 0.2 证据类型（EV）

设计侧 playtest 只承认下列 7 类证据。**任何验收条目的"通过"必须挂靠至少一类证据，无证据的通过判定一律视为 MISSING。**

| 代码 | 证据类型 | 采集方式（无需引擎） | 适用 |
|---|---|---|---|
| **EV-1** | 会话观察记录 | 主试按 §4.2 逐步记录玩家行为 + 时间戳 | 行为是否发生、卡点定位 |
| **EV-2** | 出声思维（think-aloud）逐字摘录 | 要求被试边玩边说，录音后摘录关键句 | 玩家**为什么**这么做、认知是否正确 |
| **EV-3** | 主观量表 | 赛后问卷，1–5 李克特（§4.6） | 趣味性、公平感、可读性、回访意愿 |
| **EV-4** | 行为计数 | 主试手工记账表（选择分布、重试次数、犹豫时长） | 决策分布、是否坍缩为主导策略 |
| **EV-5** | 战报/战斗日志文本 | 战斗结束页文本或纸面推演结果 | 可读性六要素、克制归因、回合数 |
| **EV-6** | 经济流水表 | 表格（Excel/CSV）逐日记账，可纯人工推演 | 通胀率、sink 断崖、内容耗尽 |
| **EV-7** | 设计对照评审 | 文档条款 vs 实际表现逐条比对，由 QA 出具 | 护栏是否被触发、口径是否一致 |

> **设计侧说明**：EV-4 / EV-6 在无埋点的情况下，用**主试手工记账 + 表格推演**即可达成——这是本框架刻意做到"不依赖引擎"的关键。

## 0.3 判定口径（三档，advisory）

| 判定 | 含义 | 后续动作 |
|---|---|---|
| **PASS** | 通过标准全部满足，证据充分 | 归档，进入回归观察 |
| **CONCERNS** | 标准满足但证据不足 / 边缘通过（余量 <10%）/ 出现反向信号 | 记录 + 下一场次重点复测，不阻塞 |
| **FAIL** | 未达通过标准，或触发明确失败信号 | 开缺陷单（§4.7），升主理人裁决 |

**维度判定 = 该维度下所有条目的最差判定。**
**总门（advisory）**：出现任一 **Blocker** 缺陷，或 **≥2 个维度判 FAIL** → 本轮 playtest 总判 **FAIL**。
> **质量门是建议性门控**：QA 给判定，**放行与否由用户（主理人 游承峰）决定**。本框架不代替决策。

# § 1 Playtest 目标与评估维度

> **总目标**：验证《主案》§1 承诺的核心体验——"**航海 + 资源管理为主轴、战斗为短平快支援原子、付费不破体制平衡、长线可经营**"——在实际游玩中**真实发生**，而不只是文档里成立。
>
> 七个维度按"**玩家从第一分钟到第三十天**"的时间轴排列：M6（进得来）→ M1（玩得下）→ M2（有挑战）→ M4（看得懂）→ M5（不崩坏）→ M3（不通胀）→ M7（留得住）。

## PT-M1 · 核心循环趣味性

**设计出处**：《主案》§2.1 中央原子（航海+资源管理）、§2.2 三层循环、§2.5 一分钟循环八步；《圣经》§1.2.1 微观循环 + 每日钩子四项。

**核心问题**
1. 《主案》§2.5 的八步闭环（看地图 → 选目标 → 读敌情 → 调编队 → 出航 → 看演出 → 收菜 → 复盘）在无提示条件下能自然跑通吗？
2. 玩家的"agency 感"是否真的集中在步骤 3–4（读敌情 + 调编队）？还是被战斗演出抢走了主观戏份（违背"战斗=支援原子"定位）？
3. 循环的**驱动力**来自哪里——目标感（重建秩序）、资源滚雪球、还是纯粹的奖励拉扯？

| 指标 | 通过标准 | 失败信号 | 证据 |
|---|---|---|---|
| 自发二次循环率 | ≥80% 被试在完成首次闭环后 **3 分钟内无提示自发发起第二次出航** `QA_KNOB` | 需主试提示才继续 | EV-1 |
| 单循环时长 | 中位数落在 **1–3 分钟**（对齐《主案》§2.5 的 1:45 设计值 ±100%） | >5 分钟（拖沓）或 <40 秒（无决策，退化为点击） | EV-1 |
| agency 归因 | 赛后问"这局最影响结果的是你哪个决定"，**≥70% 指向选目标 / 调编队**（步骤 2–4） | ≥30% 回答"看运气"或"看抽卡" | EV-2 |
| 主轴权重感知 | 主观量表"航海与资源调度比战斗更重要" ≥ **3.5/5** | ≤2.5（战斗喧宾夺主，违背《主案》§4.1） | EV-3 |
| 循环趣味量表 | "我想再来一次" ≥ **4.0/5** | ≤3.0 | EV-3 |
| 每日钩子有效性 | 《圣经》§1.2.1 四钩子（洋流指向 POI / 护岛入账 / 联盟任务 / 赛季进度条）中，被试能主动说出 **≥2 项** | 仅能说出 0–1 项 → 日常驱动力不足 | EV-2 |

**判定**：6 项指标 ≥5 项达标 = PASS；4 项 = CONCERNS；≤3 项 = FAIL。

## PT-M3 · 数值通胀预警

**设计出处**：《经济》§5 三层护栏、§5.3 D5 验收口径提案、§4.3 容量比、§5.4 内容耗尽；《圣经》§5.4 通胀监控与红色警报；《契约》D5。

**核心问题**
1. D5「通胀率 ≤5%/天」在**已锁定口径**（滚动 + 参考玩家档案）下真的守得住吗？
2. **sink 断崖**（《经济》§4.3：第 25 日造船投满 → 日投入 −37% → 通胀 0.55%→3.88%）是否被 `refit` 修复？
3. 玩家的**主观**"资源该花哪"是否清晰？（认知过载检查：1 池 / 4 类 sink / 3 个日产乘子）

**验收口径（引用《经济》§5.3，不改写）**

```
日通胀率 = 当日净流入 ÷ 前一日池存                    （滚动口径）
REFERENCE_PLAYER = { invest_rate: 0.80,
                     支出优先级: 领地维护 > 主队5卡升级 > 造船 > 岛屿开发 > 船体改装,
                     占领节奏: 受 GDD-02 进度曲线约束的可达序列 }
通过线 = 该档案下 30 日峰值日通胀 ≤ 5%
```

**样本量说明（诚实边界）**
- 设计侧 playtest 是**定性**方法。n=5 可发现约 80% 的可用性问题（Nielsen 经验法则），本框架据此设定 S-A n≥5。
- **本框架的任何结论都不得宣称统计显著性**。所有百分比阈值均为"观察门槛"而非"统计推断"，QA 报告中必须标注 `n=__`。
- 需要统计结论的项目（胜率分布、掉率验证）一律走 **S-C 表格推演**或上线后真实数据，不靠小样本 playtest 硬推。

## 5.2 单场执行流程（标准 8 步）

```
1. 开场（5 min）：签署录音同意 → 说明"测的是游戏不是你" → 强调出声思维
2. 基线问卷（3 min）：SLG 经验、付费习惯、persona 匹配度
3. 自由游玩（主体）：主试全程不提示；仅在 L3 卡点（>90s）后介入并记录
4. 事件驱动追问：关键决策点后追问"你刚才为什么选它"（不打断心流）
5. 收尾任务（10 min）：定向任务（如"请打下 FR_09"）以覆盖未触达条目
6. 赛后问卷（5 min）：§4.6 量表 + 4 道开放题
7. 深访（10 min）：针对本场 CONCERNS/FAIL 项定向追问
8. 当日归档（主试，30 min）：填 §4.3 指标表 → 开缺陷单 → 出 §4.8 结论卡
```

**主试纪律（防污染）**
- 不解释规则、不评价玩家操作、不透露"正确解法"；L3 卡点介入时只给**最小提示**并记录提示内容。
- 不引导性提问（禁止"你是不是觉得克制很有用？"，应问"你刚才为什么换那张卡？"）。
- **观察与推断分离**：见 §4.2 记录纪律。

## 5.3 回归与稳定性（设计侧）

| 项 | 规则 |
|---|---|
| **回归触发** | 任一 **Blocker / Critical** 缺陷修复后，**必须重跑该缺陷所属维度的全部条目**（不只重跑该条） |
| **联动回归** | 战斗常量变更（`SEG_DECAY` / `DEF_COEF` / `ARMOR_CAP`）→ 强制联动重跑 PT-M2 四档 + PT-BT-04/05/06 + PT-GR-03。**依据**：《经济》§6.3 已明确"下调会削弱疾风、降低整体 DPR，必须与 GDD-02/03 一次性联动复跑" |
| **不稳定条目（flaky）** | 同一条目在相同口径下**两场判定相反** → 标记 `UNSTABLE`，**从当轮判定中隔离**（不计入维度判定），并开 Major 缺陷排查根因（常见根因：口径未固定、被试画像差异过大、主试记录标准不一） |
| **禁止行为** | 不得因"某场偶然通过"就撤销既有 FAIL；不得在同一轮内更换通过标准或口径 |
| **口径冻结** | 一轮 playtest 开跑后，**§0.4 六项前置口径与所有 `QA_KNOB` 阈值全部冻结**，中途变更即本轮作废重跑 |
