## 7.0 设计意图（设）—— 先想清楚"为什么好玩"

> 本卷 v0.1 只有公式与数值，被评"数值模拟规格、非游戏设计"。本节省略补回：核心系统、幻想、上手—精通曲线、玩家分布、引导。

### 7.0.1 核心系统（系统集中 / 删去则游戏不成立）
- **本作战斗的核心系统 = 编队构筑（Deckbuilding）作为唯一策略表达**。
- auto-battle 是**呈现层**，不是核心；玩家爽点在于"我组出的 fleet 打出了我想看的场面"，而非手操。
- 判定法（删除法）：去掉实时操作不影响游戏（本就无）；去掉**编队/COST/体系选择/协同搭子**则游戏塌缩为掷骰子 → 故构筑即核心。
- 所有外围系统（船体基建、科技、联盟）应向"构筑表达"收束，而非自成一套数值。

### 7.0.2 幻想主轴与 Aesthetics 目标
- **幻想**：mythological naval war —— 每张卡是一个"神话单位/舰种"，玩家是**舰队指挥官（θ）**。
- **Aesthetics（审美目标）**：① 可读性（看得懂胜负）② 构筑自豪感（Competence：我组得对）③ 自定义（Autonomy：我的 fleet 我的风格）。
- 对应 3 Universal Wants：Competence（易上手难精通）/ Autonomy（自定义 fleet）/ Relatedness（联盟共舰、GVG 读对手）。

### 7.0.3 易上手难精通：连续—离散—连续 ramp
映射到 SLG（非动作游戏的连续操控）：
- **底端连续（低精力玩家）**：auto-battle 演出 + 战斗日志可读性 → 看着爽，不需操作。守住"看也能玩"的人群。
- **中间离散（核心 / 策略表达）**：**编队 / COST 预算 / 体系选择 / 协同搭子** → "计"的主战场，博弈充分在此发生。
- **顶端连续（高手）**：跨赛季 meta 读对手、反制构筑、环境（洋流/赛季主题）自适应 → 用连续变量（版本/环境）做深度。

### 7.0.4 玩家分布（时间 × 精力 × 金钱）与 demo 服务段
- **时间×精力×金钱**构成有效人群；区间外=失效。
- demo 优先服务：**中低精力 + 中等时间 + 全金钱段**的"构筑党"与"观战党"——即核心系统（编队）可浅玩（预设 deck）可深玩（协同网）。
- 高精力硬核（顶 Continuous meta）不在 demo 范围，留正式期；鲸鱼（金钱段）通过收集/稀有卡满足 Autonomy，不靠数值碾压（护栏见 7.5）。

### 7.0.5 引导（Onboarding）：软引导而非"信仰之跃"
- **原则**：细致软引导降精力成本=更大人群；稀疏航标（信仰之跃）=懒惰设计，部分玩家血本无归。
- 新手岛 FR_01 用"体系教学"：先给同体系 2 张，打赢后提示"试试克制"；战斗日志高亮克制关系（见 7.11）。
- 文档/教学**内置**于游戏（diegetic）：克制说明在卡面可见，不藏进 wiki。

## 7.1 定位（计）：auto-battle + 确定性纯函数
- **形态**：auto-battle（自动战斗）+ 确定性结算。玩家布阵后即交给纯函数，无需手操。
- **入口**：PVE 占岛守卫 / 海域 Boss / GVG（玩家间）共用同一结算内核。
- **为什么是纯函数**：① 技术架构要求 zk 战斗证明——只有纯函数才能"输入承诺 → 输出战斗日志 → 证明结算合规"；② AI 易实现、可单测、可复现；③ 自动结算最省 3 人产能，demo 期不依赖美术/手操。

## 7.2 实体（含角色身份）
```
Fleet = 1 Ship + CrewArray(≤5 槽位, 受 Ship.capacity COST 上限约束)
CrewCard {
  id, name,
  system,                 // flame/ironwall/wind/tide
  archetype,              // 角色身份(见 cards.json)：焚烧者/壁垒/疾袭/潮涌...
  rarity,                 // R/SR/SSR/UR（=archetype 完成度，非纯数值）
  identity,               // 一句话动词：这张卡"做什么"
  atk, def, spd, hp, cost,
  skill,                  // {name,type,desc}
  synergy,                // 协同钩子：与谁搭/体系内 chain
  countered_by            // 被谁克（可读性，见 7.11）
}
Ship     { name, armorType(轻甲/重甲/能量盾), armor, speed, capacity(COST上限), atkMod, defMod }
Env      { season, current, windDir, tidePhase }   // 决定 envMod
```
- `system` ∈ {flame 烈焰, ironwall 铁壁, wind 疾风, tide 潮汐}
- `armorType` ∈ {light 轻甲, heavy 重甲, shield 能量盾}
- **角色身份优先于稀有度**：同体系内靠 archetype 区分功能（坦克/输出/辅助/控制），稀有度只决定该身份的完成度与扩展技。详见 `数据层/cards.json` 与 `协同网矩阵.md`。

## 7.3 四体系 ↔ 伤害/护甲/环境 映射
| 体系 | 主伤害类型 | 护甲倾向 | 多段/特性 | 环境偏好（赛季主题） |
|---|---|---|---|---|
| 烈焰 flame（中华） | 燃烧 DoT | 轻甲 | 持续伤害 | 无风+能量（火药坊）/ 顺风+攻速 |
| 铁壁 ironwall（高加索） | 物理 | 重甲 | 高减伤 | 逆风+护甲（逆风盛行 +15%） |
| 疾风 wind（信风） | 物理·多段 | 轻甲 | 额外出手 | 顺风+攻速（信风劲吹 +15%） |
| 潮汐 tide（亚特） | 能量 / 控制 | 能量盾 | 充能/控场 | 顺潮涌动 充能 +20% |

**伤害类型 → 护甲克制**（核心，写死在代码常量）：
| 伤害类型 \ 护甲 | 轻甲 | 重甲 | 能量盾 |
|---|---|---|---|
| 物理（铁壁/疾风） | ×1.0 | ×0.7 | ×1.15 |
| 燃烧（烈焰） | ×1.2 | ×0.85 | ×1.0 |
| 能量（潮汐） | ×1.1 | ×0.8 | ×0.6 |

> 体系互克三角：物理打重甲减伤、打能量盾增伤；能量打能量盾大幅减伤（盾克能量）——形成环，避免单体系碾压。

## 7.4 伤害公式
```
单段伤害 = round( baseAtk
        × restraintCoef(克制方 RESTRAINT=1.3 / 被克 RESTRAINT_DISADV=1/1.3)
        × typeCoef(见 7.3 护甲表)
        × envMod(赛季主题, 见 7.6)
        × shipAtkMod
        − effectiveArmor )

effectiveArmor = target.armor × (1 − pierceRate)     // 穿甲率默认 0，铁壁船体提供穿透
DoT(烈焰)      = round(baseAtk × dotRate × restraintCoef) // 持续 k 回合；吃克制（DOT_APPLIES_RESTRAINT=true）
真实伤害      = round(raw × restraintCoef)              // 可无视护甲/typeCoef，不可无视克制
control(潮汐)  = {prob, duration}                       // 概率/时长，深渊回响加成 prob
```

## 7.5 克制 +30%（商业护栏硬约束）
- 四体系两两互克形成环：烈焰→铁壁→疾风→潮汐→烈焰（顺环克制，逆环被克）。
- 克制方对被克制方**最终伤害 ×1.3**；被克方对克制方 **×(1/1.3)**（对称环）。
- 系数写进 `constants.md`：`RESTRAINT` / `RESTRAINT_DISADV`；不在任何卡牌/皮肤数据里。
- **作废口径**：被克 ×1.0；DoT 不吃克制——已废止。

## 7.6 回合结构
```
1. 初始化：按 spd 降序排出手顺序；envMod 由 Env 当前主题计算
2. 每回合：
   a. 按出手序，每张卡结算一次主动（单段 or 多段）
   b. 疾风体系多段：spd 每超阈值 20，额外 +1 段（上限 +2）
   c. 结算 DoT（烈焰）/ 控制判定（潮汐）
   d. 刷新 envMod（洋流/赛季主题按回合推进）
3. 任一方 hp 全清 → 结束，winner = 存活方
4. 回合上限 GUARD_MAX_ROUND = 30，超时按剩余总 hp 比例判定
```

## 7.7 COST 与舰队规模（博弈充分）
- 舰队 COST 上限 = `Ship.capacity`（demo 默认 **10**）。
- 卡 cost：R=1 / SR=2 / SSR=3 / UR=4 → 限制强力单位数量，强制体系搭配（不能全堆 UR）。
- 槽位 = **5**。
- **博弈充分**：同 COST 内选哪张是真实权衡——因卡按 archetype 区分功能（坦克/输出/辅助/控制），不是纯数值梯度（详见 7.2 / cards.json）。
- 示例合法编队：UR×1(4) + SSR×1(3) + SR×1(2) + R×1(1) = 10，占 4 槽；剩 1 槽可补 R。

## 7.8 组合技（协同网，见 协同网矩阵.md）
```
actualPower = skillBase
    × shipSynergy(船体基建匹配体系 ? 1.2 : 1.0)
    × envMod(赛季主题对体系偏好)
```
- 体系内 chain（如 烈焰互燃：多张 burn 叠 DoT 更快清场）、跨体系 combo（潮汐控+疾风多段=锁定爆发）、ship-card 匹配（火药坊→烈焰 +15%）。
- 协同网是本作"难精通"深度的来源，详见 `数据层/协同网矩阵.md` + 矩阵图。

## 7.11 战斗可读性（日志呈现规范）★C
> 目的：让玩家（尤其 auto-battle 不手操者）**看清为何赢 / 为何被克**，满足 7.0.2 可读性 + 7.0.5 引导。

**战斗日志必须逐段记录并呈现**：
1. 出手方 + 技能名 + 体系/archetype 标签
2. 伤害分解：`基础×克制1.3×护甲系数×环境×船体 − 有效护甲 = 最终`
3. **克制高亮**：当 restraintCoef=1.3 时，日志标「克制！+30%」；被克时标「被克制」
4. **护甲交互提示**：如「燃烧打重甲 −15%」「能量打能量盾 −40%」
5. DoT/控制独立行：`第N回合 燃烧 跳X / 眩晕 持续Y回合`
6. 结束页小结：`体系克制：A克B → A 占优` / `COST 利用：A=10 B=8`

**卡面可读性原则（diegetic）**：
- 每张卡明示 `countered_by`（被谁克）与 `strong_against`（克谁），不藏进 wiki。
- 体系色 + archetype 图标在 UI 常驻，降低认知成本。

## 7.12 失效边界（崩坏护栏）★C
> 目的：定义每个系统崩坏点，防协同网/技能叠加把战斗打爆。全部锁进 `constants.md`。

| 崩坏点 | 护栏常量 | 值 | 说明 |
|---|---|---|---|
| 永久眩晕 permastun | `MAX_STUN_ROUND` | 3 | 单目标累计控制回合上限，超出免疫 |
| 无限 DoT 叠加 | `MAX_DOT_STACK` | 5 | 同目标燃烧层数上限，超出不增伤 |
| 能量盾吸收溢出 | `MAX_SHIELD_MULT` | 2.0 | 盾量 ≤ 本体 hp ×2，防盾比血厚 |
| 多段上限 | `MAX_EXTRA_HIT` | 2 | 疾风额外段上限（阈值触发不超） |
| 单场时长 | `GUARD_MAX_ROUND` | 30 | 超时按剩余 hp 比例判，防互奶不死 |
| 单卡数值上限 | `STAT_CAP` | atk≤200/def≤200 | 防单卡数值膨胀碾压克制 |
| 同体系纯堆 | `SAME_SYS_SOFT_CAP` | 4/5 槽 | 同体系卡 ≤4，强制搭配（与 COST 双约束） |

> 所有护栏为设计锁定值（非 PLAYTEST_KNOB），改动需 team-lead 评审——这是"数值不崩"的硬闸。

## 7.13 最小可跑 demo 战斗链路（验收用）
选海域 → 顺流靠岛 → 打 1 个 POI(轻 PVE) 得资源/卡 → 抽/预设 deck → 组 1 队(≤COST，按 archetype 搭协同) → 打赢 1 场 PVE 守卫。每一步可单测，纯函数 `ResolveBattle` 用 D3 验收（输入两 fleet+env+seed，输出 deterministic winner + 可读性日志）。
