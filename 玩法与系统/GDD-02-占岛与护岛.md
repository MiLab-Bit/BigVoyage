## 1. 概述

占岛是 Demo 的**进度骨架**：12 座岛构成一条从霜锚港到渊眼的难度阶梯，玩家每攻下一座，就把"探索产出 → 战力成长 → 打更硬的岛"这个雪球推大一格。护岛则把一次性的战斗胜利转化为**持续性的被动收益**（日产），是经济系统的第二 faucet。

**一句话定位**：占岛 = 把「战力」兑换成「地盘」；护岛 = 把「地盘」兑换成「时间流逝带来的收益」。

**在支柱上的位置**
- 支柱 1「胜负在出航前决定」的**验收面**——守卫编成全明文，玩家应能在点击出航前就知道结果。
- 支柱 3「航海是主轴，战斗是标点」的**标点本身**——12 场守卫战是 Demo 全部的战斗内容。

**本文最重要的一个结论**：`FR_12 渊眼`（Boss 岛）在当前数值下**可胜编队 = 0 / 11,653**，且根因不是"输出不够"，而是**铁壁护甲光环叠加撞到 0.90 护甲硬顶**造成的等效 HP ×10。**五个单因子修复方案、九种两两组合，实测全部 0% 可胜**。可行方案只有组合拳，见 §6.4。

## 4. 机制

### 4.1 攻岛流程

```
RaidIsland(player, island) -> RaidResult
  前置断言：
    island.state >= scouted                 // 必须先抵达（GDD-01 §4.1）
    island.owner != player
    stamina >= STAMINA_COST_RAID            // = 8
    fleet 通过三约束校验（COST≤10 / 槽≤5 / 同体系≤4）
  步骤：
    1. stamina -= 8                                        // 无论胜负都扣
    2. env    = islands[island].sea_theme.env_bias         // Demo 固定冻洋
    3. guard  = build_guard_fleet(guards[island])          // 含 hp_mult 放大
    4. r      = ResolveBattle(fleet, guard, env, seed)     // GDD-03
    5. if r.winner == "A":
         island.owner = player
         island.dev   = 0
         island.captured_at = now
         grant(FIRST_CAPTURE_BONUS[tier])                  // §6.6
       else:
         无任何损失（不掉卡、不掉资源、不掉耐久）
    6. 返回 RaidResult{winner, log, commitment}
```

> **失败零惩罚**是刻意设计：支柱 1 的前提是"玩家可以先算"，那么算错的代价应该是**时间（体力）**而不是资产。惩罚资产会让玩家倾向于不试错，反而学不会系统。

### 4.2 守卫编成构造

```
build_guard_fleet(spec):
  units = [card(id) for id in spec.cards]                  // 与玩家用同一张 cards.json
  for u in units:
      u.hp = round(u.hp_base × spec.hp_mult)               // 唯一的强度旋钮
  ship = ships[spec.ship_id]                               // 全部 SHIP_IRON（重甲）
  return Fleet(units, ship)
```

守卫**复用玩家卡表**——这是关键的可读性设计：玩家在情报页看到的守卫，都是他自己认识（或想要）的卡，"这个岛难在哪"是可推理的，而不是一堆黑盒数字。

### 4.3 主权与日产

| 概念 | 定义 |
|---|---|
| 主权 `owner` | 岛屿归属。Demo 单人，只有 `none` / `player` 两态 |
| 开发度 `dev` | 0~4，用 `strategic` 投入提升（见 `GDD-04`），每级 +25% 日产 |
| 邻接加成 | 每有 1 座**已占领的邻接岛**，本岛日产 +10% |
| 结算时点 | `daily_00_clear`，与体力/POI 槽位同一时钟 |
| 领地维护费 | 每日自动扣 `日产 × UPKEEP_RATE(0.40)` —— 常驻 sink，见 `10-经济数值模型` §5 |

### 4.4 护岛日产公式（显性）

```
yield_i = ISLAND_DAILY_YIELD × TIER_M[tier_i] × (1 + DEV_BONUS × dev_i) × (1 + ADJ_BONUS × adj_owned_i)

  ISLAND_DAILY_YIELD = 120        [资源点/日]        （冻结）
  TIER_M   = {start:0.5, light:1.0, heavy:2.5, boss:6.0}   [无量纲]  ← PLAYTEST_KNOB
  DEV_BONUS = 0.25                [无量纲/级]        dev ∈ [0,4]
  ADJ_BONUS = 0.10                [无量纲/岛]        adj_owned = 已占领的邻接岛数
  net_i    = yield_i × (1 − UPKEEP_RATE 0.40)      [资源点/日]  实际到手
```

**三项输入全部链上可读**（`tier` 静态、`dev` per-island mapping、`adj_owned` 可由 owner mapping 推出），因此该公式**可以做成链上纯函数**——这直接回应工程 A-07，详见 `10-经济数值模型` §8 O-5。

### 4.5 情报与预测（支柱 1 落地）

出航确认弹窗必须给出**三级结论 + 理由**，而不是一个胜率数字：

| 结论 | 判据 | 展示 |
|---|---|---|
| 可胜 | 模拟剩余 HP 占比 > 25% | 绿色「预计 N 回合取胜，剩余战力 X%」 |
| 险胜 | 剩余 HP 占比 0~25% | 黄色「险胜，任何一张卡换下都可能翻盘」 |
| 不可胜 | 模拟败北 | 红色「不可胜」+ **最短改进路径**（如「缺少烈焰输出：守卫为铁壁重甲，你的物理伤害被 −30% 惩罚」） |

> 因为 `ResolveBattle` 是确定性纯函数，**客户端可以在出航前本地跑一遍拿到确切结果**。所以这里不是"胜率预测"，是**确切答案**。这是本作相对同类 SLG 最大的体验差异点，必须做，且必须在 UI 上讲清楚。

### 6.4 🔴 平衡红线 B3 · FR_12 不可通关的根因与解法

**现象**：全收集 20 卡下，`可胜编队 = 0 / 11,653 = 0.0%`。

**归因（`_scratch/sim6.py` / `sim7.py`）—— 不是输出不够，是护甲**

FR_12 守卫是铁壁重甲编队，护甲减免的实际叠算链条为：

```
base_armor  = def / (def + 100)
× 山岳守望「全队护甲 +15%」
× 要塞类「全队护甲 +25%」
× SHIP_IRON defMod 1.08
+ 铁砧卫「自身 +0.08」平坦加值
→ effective_armor 撞上 ARMOR_CAP = 0.90
→ 守卫只吃 10% 伤害 → 等效 HP × 10
```

守卫账面总 HP 6,354，等效 HP ≈ 63,540；而玩家最优编队 30 回合总输出远不足此数——**任何输出侧的加强都是杯水车薪**。

**单因子扫描结果（全部 0% 可胜）**

| # | 单独施加的修复 | 结果 |
|---|---|---|
| 1 | 玩家换 SHIP_IRON | 0% |
| 2 | 养成 ×1.5 DPR | 0% |
| 3 | Boss `hp_mult` 1.8 → 1.0 | 0% |
| 4 | `ARMOR_CAP` 0.90 → 0.70 | 0% |
| 5 | 段数公式修正（卡面段数） | 0% |
| — | **上述任意两两组合（9 组）** | **全部 0%** |

> 这条结论对 `GDD-03 §6.5` 是重要补充：那里推荐的「方案 1：养成轴 Lv1–10（DPR ×1.5）」**单独上是不够的**，实测仍然 0%。必须配合护甲顶下调 + Boss 编成重配。

**可行解（组合拳，`_scratch/sim10.py` 五卡终选）**

固定：玩家 SHIP_IRON + `gm=1.15` + `ARMOR_CAP=0.80` + `SEG_DECAY=0.40`。

| b | 同 a，`hp_mult=1.5` | 12 | 4,432 | 10.10% | ✅ 保守备选（若嫌 a 太松） |

> **推荐方案 a**。1,590 种可胜编队（13.65% × 11,653）意味着玩家有**多条解题路径**，符合支柱 1「可算且多解」；而 86% 的失败率保证 Boss 仍是需要认真构筑的门槛。

**⚠️ 代价申明**：方案 a 需要动 `ARMOR_CAP`（0.90 → 0.80），这是 constants 层的值。若主理人不愿动冻结常量，**唯一的替代是 `GDD-03 §6.5` 方案 3：把 FR_12 移出 D4 必过项**，Demo 只验收到 heavy 岛。两条路都合规，请二选一。

## 7. 边界情况

| # | 边界 | 处理 |
|---|---|---|
| E1 | 攻岛战平局（`draw`） | **按未占领处理**，挑战方不获得主权（与 GDD-03 E2 一致） |
| E2 | 满 30 回合未分胜负 | 按剩余总 HP 判；HP 完全相等时**挑战方（A）胜** → 岛屿易主。UI 必须明示此规则，否则玩家认为是 bug |
| E3 | 体力不足 8 但玩家坚持攻岛 | 按钮置灰；**不允许透支、不允许用资源买体力**（Demo 无体力购买） |
| E4 | 攻打未 `scouted` 的岛 | 前置断言拦截。海图上灰显不可点 |
| E5 | 已占领岛被重复攻打 | 按钮变为「已占领」，不可再攻。Demo 无失守机制 |
| E6 | 同一天连续攻多座岛 | 允许，只受体力限制（120 / 8 = 最多 15 次攻岛）。但每次攻岛挤占 1.33 次 POI |
| E7 | 玩家在 FR_12 胜利后 | 触发 Demo 终局结算界面；岛屿仍保留日产，游戏不结束 |
| E8 | `dev` 已达 4 仍投入资源 | 拦截，按钮显示「已达开发上限」 |
| E9 | 占领后邻接加成的重算范围 | 只重算**该岛及其直接邻接岛**（≤5 个），不做全图重算 —— 保证链上更新的 gas 有界 |
| E10 | 首占奖励与链上确权的时序 | 奖励发放必须与 `owner_changed` 在**同一原子事务**内，否则出现"发了奖但没占到岛"的不一致 |
