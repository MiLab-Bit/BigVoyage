# 规格层 · 编队与演出锁定（AI 可执行）

> 本文是「规格层」：给 AI agent 直接吃的类型/签名/协议。叙事见世界观文档，玩法意图见 `玩法设计-编队驱动与战斗演出.md`，数值基线见 `数据层/cards.json` + `constants.md`。
> 已锁决策：① 情报全透明 ② 位序双轴(前中后+速度序) ③ 多指令优先级列表 ④ 2D 演出。

---

## §1 决策锁定表

| 维度 | 锁定值 | 对系统的影响 |
|---|---|---|
| 情报 | **全透明**（看得见对方完整舰队） | 无 fog；puzzle=已知敌下的优化克制构筑；删除情报分级逻辑 |
| 位序 | **双轴**：positional_row(前/中/后) × speed_order(整数序) | 两轴正交，构成 2D 决策空间 |
| 预设指令 | **多指令优先级列表** PriorityDirectives[] | 战前绑定舰队，非实时输入 |
| 演出 | **2D** | 事件驱动回放，DOM/Canvas 皆可 |

## §2 数据 Schema（单一真源：constants.md 只读引用）

### 2.1 舰队定义 FleetDef（输入 ResolveBattle）
```ts
type SystemId = 'flame' | 'iron' | 'gale' | 'tide';
type Row = 'front' | 'mid' | 'back';

interface FleetCard {
  card_id: string;          // → cards.json
  row: Row;                 // 前中后：影响受击优先级与技能作用域
  speed_order: number;      // 同 round 内激活序，小者先；同值按 card_id 字典序
}

interface Directive {
  priority: number;         // 1=最高；列表按 priority 升序执行，遇冲突取高优先级
  type: 'focus' | 'kite' | 'survive' | 'combo_bait';
  // focus:   优先集火 target_tag 指定的敌方卡
  // kite:    本队 low_hp 单位后撤(降为 back 受击权重)
  // survice: 残血(<threshold%) 单位跳过进攻、保命
  // combo_bait: 优先触发某 synergy（牺牲单卡换 combo）
  target_tag?: string;      // 敌方 card_id 或 archetype
  threshold?: number;       // 0-100，配合 survice/kite
}

interface FleetDef {
  owner: string;            // 指挥官 id
  cards: FleetCard[];       // ≤5，COST 和 ≤ MAX_COST(10)
  directives: Directive[];  // 多指令优先级列表（可空）
}
```

### 2.2 战斗环境 BattleEnv
```ts
interface BattleEnv {
  sea: SystemId;            // 海域 → 环境修正（冻洋铁壁+）
  seed: number;             // 确定性随机源（仅用于非确定性呈现抖动，不影响胜负）
  modifiers: Record<string, number>; // 来自 constants.md 的环境系数
}
```

### 2.3 战斗纯函数签名（保持无实时输入）
```ts
// 指令是 fleet 定义的一部分 → 不破坏纯函数
function ResolveBattle(
  fleetA: FleetDef,
  fleetB: FleetDef,
  env: BattleEnv
): BattleLog;              // 确定性：同参永远同输出
```
> **zk 对齐**：BattleLog 可哈希承诺；seed 仅用于演出抖动，不参与结算。

## §3 位序双轴如何进结算（给战斗 agent 的硬规则）

| 轴 | 作用域 | 规则 |
|---|---|---|
| **positional_row** | 受击 & 技能作用域 | 敌方默认优先打 `front` → `mid` → `back`；AOE/穿透可跨 row；后排控卡只对 mid/back 生效 |
| **speed_order** | 同 round 激活序 | 每 round 内按 speed_order 升序结算技能；高 speed 先手控场可打断低 speed 的蓄力技 |

**决策空间示例**（同 COST 的真实权衡）：
- 把核心输出放 `back`+高 `speed_order`：先手但需前排铁壁扛线，否则被切。
- 全 `front` 铁壁墙：稳但速度慢、被高 speed 控卡压制。
- 这层 2D 正交 = 玩家在编队界面要解的「摆位谜题」。

---

## §4 多指令优先级（战前绑定，结算时解释）

- 列表按 `priority` 升序；同一 round 内若两条指令冲突（如 focus 集火 vs survice 保命），取高优先级。
- `combo_bait` 是进阶指令：主动牺牲单卡站位换 combo 触发（呼应"反制即协同"深度）。
- **不引入实时输入**：指令在 `FleetDef.directives` 里，开战前定死。

---

## §5 情报全透明（无 fog）

- 开战前 UI 展示敌方 `FleetDef`（cards/row/speed_order/体系分布/威胁卡）。
- **预测仪表盘**（编队 UI 常驻，吃 constants.md）：
  - 对当前敌情：本队 `克制 +X% / 被克 −Y%`（X,Y 来自 RESTRAINT=1.3 推导）
  - `combo 触发提示`：列出将满足的 synergy（火墙/锁定爆发…）
- 这把"数值对撞"变成**可见可预测的博弈**——纯 auto 下玩家唯一的信息优势来源是"自己算得比对面准"。

## §6 2D 演出规格（给演出 agent 的事件协议）

### 6.1 BattleLog → 2D 回放事件流
`ResolveBattle` 输出结构化 `BattleLog`，演出层只消费它（不反向依赖逻辑）：
```ts
interface BattleEvent {
  t: number;               // 时间轴(ms)，用于 2D 时间轴拖动/回放
  type: 'deploy'|'skill'|'hit'|'dot'|'control'|'combo'|'down'|'end';
  src: string;             // 发起卡 card_id
  dst?: string;            // 目标卡 card_id
  sys: SystemId;           // 伤害/技能体系 → 决定颜色(烈焰橙/铁壁银/疾风青/潮汐紫)
  amount?: number;         // 伤害/治疗量
  restraints?: boolean;    // 是否克制命中 → 触发红光高亮
  combo_id?: string;       // 触发的 combo（火墙等）→ 专属 2D 特写
  row?: Row;               // 受击单位所在 row → 2D 站位渲染
}
```

### 6.2 2D 渲染硬规则（可读性三原则落地）
1. **克制高亮**：`restraints=true` 时 dst 冒红光 + 减益图标。
2. **类型色**：`sys` 映射固定色板（见 constants.md `SYS_COLOR`）。
3. **可暂停/回放**：时间轴 `t` 可拖动 → 研究权（纯 auto 必需）。

### 6.3 2D 技术建议（demo）
- 轻量：Canvas 2D 画舰队站位(row 为 Y 轴、speed_order 影响入场动画序) + DOM 叠伤害跳字。
- 节奏：疾风(fast) 事件间隔短；铁壁(slow) 间隔长 → 体系性格外化。
- 爽感：combo 事件触发 2D 同屏特效（火墙=橙焰+银盾叠层）。
