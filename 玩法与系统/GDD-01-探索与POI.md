## 1. 概述

冻洋 12 岛构成一张稀疏邻接图（**Demo 范围 = 12 岛（FR_01–FR_12）；全量赛季 = 36 岛（3 海域 ×12）**，见登记册 [B5]）。玩家以霜锚港（FR_01）为原点，用**每日体力预算**在图上做「去哪、去几次、留多少体力打守卫」的分配决策。POI 是本作**唯一的资源与卡牌一级入口**（占岛日产是二级、被动入口），因此 POI 的产出速率直接决定整个 Demo 的节奏长度。

**一句话定位**：POI 探索 = 把「体力」这一日常预算，换成「战略资源 + 船员卡 + 船图纸」三种战力货币的转换器；玩家的策略在于**换在哪张岛上**。

**在支柱上的位置**
- 支柱 3「航海是主轴，战斗是标点」的**主要承载系统**——玩家 60%+ 在线时间应发生在这里。
- 支柱 1「胜负在出航前决定」的**信息来源**——靠岛后才解锁该岛守卫编成情报（见 §4.4）。

**本次最重要的一个修正**：原设定 `STAMINA_COST_POI = 1`，而全图 POI 槽位仅 56 个 < 体力 120 —— **体力从来不是约束**，玩家每天可以把所有 POI 打光，G1「真实取舍」在数学上不成立。§6.1 给出修正。

## 2. 目标

### 2.1 设计目标

| # | 目标 | 可验证判据 | 当前状态 |
|---|---|---|---|
| G1 | 玩家每天有一个**真实会痛的取舍** | 日体力可执行的 POI 次数 ≤ 可达槽位数 × 50% | ❌→✅ 见 §6.1 修正 |
| G2 | 航线深度带来**可读的风险梯度** | 从 FR_01 到 FR_12 最短 6 跳；单槽期望产出随 tier 单调递增 | ✅ 见 §6.2 |
| G3 | POI 是**卡池成长**的**长尾**通道（非主通道） | Demo 目标时长内卡池有可感增长 | 🟠 **口径依赖 [B4]**：槽位口径下**理论最快第 3 日**集齐（§6.5）；`1/480` 逐次口径下**期望约 288 天**（a14）。二者非矛盾，是"最好情况 vs 期望值"，见登记册 [N6]。**a14 结论：POI 为赛季级长尾，主获取靠 gacha** |
| G4 | 不引入战斗内随机 | POI 掉落随机，但**掉落发生在战斗之外**，不违反支柱 1 | ✅ |

- 不做贸易航线 / 洋流实时模拟 / 天气系统（P1+）。
- 不做 5 类航行随机事件（`00-MDA` §3.3 已归「可有」）。
- 不做 POI 节点在地图上的物理漂移刷新（Demo 用「按岛聚合的抽象 POI 槽位」，见 §4.2）。

## 4. 机制

### 4.1 海图与航行

**拓扑（已核对 `数据层/adjacency.json`：双向对称、连通、无自环）**

```
        y=0   FR_01 ── FR_02 ── FR_03 ── FR_07
                │        │        │        │
        y=1   FR_04 ── FR_05 ── FR_06 ── FR_08
                         │        │        │
        y=2            FR_09 ── FR_10 ── FR_11
                                          │
        y=3                             FR_12(Boss)
```

| 属性 | 值 |
|---|---|
| 出生岛 | FR_01 霜锚港（`tier=start`，`guard_hp=0`，无守卫） |
| 到 Boss 最短跳数 | **6 跳**（FR_01→02→05→06→10→11→12；实测另有 **3** 条等长并行路径：01-04-05-06-10-11-12 / 01-02-03-06-10-11-12 / 01-02-03-07-08-11-12。原写"2 条"已按 `数据层/adjacency.json` 复验更正） |
| 分支度 | 平均 **2.67**（16 边 / 12 节点；原写 2.5 系笔误，已按 `数据层/adjacency.json` 复验更正），最大 4（FR_05 / FR_06） |
| 死胡同 | FR_12（度=1）——Boss 岛为叶节点，符合「终点」语义 |

**航行规则（Demo）**

1. 只能从当前岛移动到**邻接岛**（`adjacency[cur]` 内）。
2. 移动本身**不消耗体力**、不消耗时间——Demo 不做真实航行耗时（避免 idle 等待）。航行以 ≤1.2s 的镜头推移演出表现。
3. 岛屿三态：`unknown`（未探明，只显示轮廓与 tier 色）→ `scouted`（已抵达，情报全开）→ `owned`（已占领）。
4. 相邻于任一 `scouted/owned` 岛的岛屿显示为 `unknown` 但**可点击**（可达）；再远的岛在海图上灰显不可点。

> 设计说明：规则 4 是**渐进解锁**，让「6 跳到 Boss」变成被逐步揭开的路径，服务 G2 与美学 Discovery；但它不是 fog-of-war——一旦抵达，情报 **100% 透明**，不违反支柱 1。

### 4.2 POI 槽位模型（Demo 抽象）

不做地图上的漂移 POI 实体。改为：**每岛每日刷新 N 个 POI 槽位**，槽位类型从该岛 `islands.json.poi[]` 按 `resources.json.poi_yield.weight` 加权抽取。

| 参数 | 取值 | 理由 |
|---|---|---|
| `POI_SLOTS_PER_ISLAND` | `start=4 / light=5 / heavy=5 / boss=2` | 全图 56 槽，见 §6.1 体力预算推导 |
| 刷新时点 | `daily_00_clear`，与体力同步 | 复用同一时钟，减少一套逻辑 |
| 可探索前提 | 岛屿状态 ≥ `scouted` | 未抵达不能刷 POI |
| 槽位消耗 | 探索一次消耗该岛 1 槽位，当日**不可恢复** | 制造「换岛」压力，防止蹲一岛刷爆 |

**槽位类型抽样（确定性）**：

```
type = weighted_pick(island.poi[], weights, H(seed_day, island_id, slot_idx))
```

同一天同一岛的槽位序列**可复现**——这对链上重放校验是必要的（见 §8 与 `10-经济数值模型` §8「链上对齐待确认项」O-3）。

### 4.3 单次 POI 结算

```
ExplorePOI(player, island, slot) -> PoiResult
  前置断言：
    stamina >= STAMINA_COST_POI
    slot.state == available
    island.state >= scouted
  步骤：
    1. stamina -= STAMINA_COST_POI                        // = 6
    2. t = slot.type                                       // crew/resource/ship/boss/crew_ur
    3. base  = POI_YIELD_TABLE[t]                          // 见 §6.2
    4. yield = base × TIER_YIELD_M[island.tier]            // 见 §6.2 —— 风险回报梯度
    5. 若 t 产出卡：card = pick_card(t, owned, H(seed_day, island, slot, "card"))   // §4.5
    6. 若 t == boss：先调用 ResolveBattle 打 POI 守卫，败则无产出（体力已扣）
    7. slot.state = consumed
    8. 返回 PoiResult{resource_delta, cards[], blueprint, log_hash}
```

> `boss` 型 POI（仅 FR_12）是**唯一带战斗的 POI**，它把 GDD-03 的战斗核接进探索循环，也是支柱 3「战斗是标点」的具体落点。

### 4.4 情报解锁（服务支柱 1）

首次抵达一岛时，一次性、永久解锁该岛：

| 情报项 | 内容 | UI 位置 |
|---|---|---|
| 守卫编成 | 5 张卡的 **id / 体系 / cost / atk / def / hp** 全量明文 | 岛屿面板 → 守卫页签 |
| `hp_mult` | 明文显示为「守卫强化 ×1.35」 | 同上，红字 |
| 环境偏置 | 冻洋：铁壁 atk +15% / 烈焰 −5%（口径以 GDD-03 §4.6 为准） | 顶部常驻条 |
| POI 槽位构成 | 今日 N 槽的类型分布（明文，不遮蔽） | 岛屿面板 → 探索页签 |
| 预测结论 | 「你当前编队 **可胜 / 险胜 / 不可胜**」+ 关键原因 | 出航确认弹窗（GDD-03 §7 预测仪表盘） |

> **红线**：Demo 不得对守卫编成做任何遮蔽。玩家看不到 = 只能赌 = 支柱 1 失效。

### 4.5 掉卡去重与保底

Demo 目标是让玩家**在有限时长内摸到 20 卡的设计空间**，而非体验 NFT 稀缺性（那是线上全量口径）。

| 规则 | 内容 |
|---|---|
| 去重优先 | `crew` 型 POI 优先从**未拥有**卡中抽取；全部拥有后转为「碎片 → 养成资源」，按 §6.4 折算 |
| 稀有度偏置 | 普通 `crew`：R 50% / SR 30% / SSR 15% / UR 5%；`crew_ur`（仅 FR_12）：UR 60% / SSR 40% |
| 保底 | 连续 8 次 `crew` 型 POI 未出新卡 → 第 9 次必出未拥有卡（Demo 内计数器，**不跨日重置**） |
| 船图纸 | `ship` 型 POI 必出 1 张图纸；图纸 +（战略资源）→ 解锁 `SHIP_IRON` / `SHIP_FLAME`（见 §6.4） |

**UI 输出规范（Should 级）**

1. 出航前，岛屿卡片显示「今日剩余槽位 x/N · 单槽期望 ~Y 资源」——让取舍**可计算**而非凭感觉。

3. 掉卡时显示保底计数器「距保底 3 次」——避免玩家产生"被系统坑了"的错觉。

## 6. 数值

### 6.1 🔴 体力预算修正（G1 的成立条件）

**问题**：`STAMINA_MAX = 120`，若 `STAMINA_COST_POI = 1`，则每日可探索 120 次，而**全图槽位只有 56 个**。体力永不成为约束，玩家每天把所有 POI 打光即可，不存在任何取舍 —— G1 直接失效，且日产会一次性冲顶。

**修正**：

```
STAMINA_COST_POI  = 6        [体力点/次]   ← 本文新增 PLAYTEST_KNOB
STAMINA_COST_RAID = 8        [体力点/次]   ← 攻岛，见 GDD-02
每日可执行 POI 次数上限 = floor(120 / 6) = 20 次
全图槽位 56 > 20  →  只能吃掉 35.7% 的槽位  →  必须选择 ✅
攻岛一次 = 放弃 1.33 次 POI  →  探索 vs 攻岛 的横向取舍成立 ✅
```

| 备选值 | 日 POI 次数 | 槽位覆盖率 | 评价 |
|---|---|---|---|
| 1 | 120 | 100%（全打光） | ❌ 无取舍 |
| 4 | 30 | 53.6% | ⚠️ 取舍偏弱 |
| **6（推荐）** | **20** | **35.7%** | ✅ 取舍明确，且恰好对齐 `daily_target`（见 §6.2） |
| 8 | 15 | 26.8% | ⚠️ 每日操作量偏少，节奏拖沓 |

### 6.2 POI 产出梯度（G2 的成立条件 + 对齐 daily_target）

**原口径**：所有 POI 一律 `POI_RESOURCE_BASE = 500`。问题是**深水区和浅水区收益一样**，玩家没有理由冒险深入——G2 的风险回报梯度不存在。

**修正**（不改冻结常量 500，只新增倍率表）：

```
单槽期望产出 = POI_RESOURCE_BASE(500) × TIER_YIELD_M[island.tier]     [资源点]

TIER_YIELD_M = { start: 0.6, light: 1.0, heavy: 2.0, boss: 4.0 }   ← PLAYTEST_KNOB
```

| tier | 岛数 | 槽/岛 | 该 tier 总槽 | 单槽期望 |
|---|---|---|---|---|
| start | 1 | 4 | 4 | 300 |
| light | 8 | 5 | 40 | 500 |
| heavy | 2 | 5 | 10 | 1,000 |
| boss | 1 | 2 | 2 | 2,000 |
| **合计** | **12** | — | **56** | — |

**日产曲线（理性玩家：20 次全投当前可达的最高 tier）**

| 阶段 | 日产上限 | 说明 |
|---|---|---|
| 仅 light 开放 | **10,000** | 20 × 500 |
| + heavy 开放 | **15,000** | 10 × 1000 + 10 × 500 |
| 满图（含 boss） | **18,000** | 2×2000 + 10×1000 + 8×500 |

> **与 SSOT 的对齐**：`resources.json.strategic.daily_target = 20000`，满图理性日产 18,000 = **−10.0%**，落在合理区间内（略低于目标，留出赛季活动 buff 空间）。
> 对比原口径：56 槽全打 = 20,150（+0.75%）—— 数字上"更准"，但**它是靠取消取舍换来的**，是假的准。

**副产品：产出曲线自然随进度爬升**（10k → 15k → 18k），而不是第 4 天就冲顶。这直接修掉了 v2 经济模拟里"第 4 步满产、之后 26 天纯堆积"的结构性缺陷。

## 7. 边界情况

| # | 边界 | 处理 |
|---|---|---|
| **E1 ⚠️ 冲突（已解）** | `POI_DROP_CREW_RATE = 1/480` 与 `poi_yield.crew` 语义打架：前者是"每次探索 1/480 概率掉卡"，后者是"crew 型槽位必掉卡"。两者同时生效则掉率相差 480 倍 | **已决（[B4]，2026-08-06 采 A Reading 2）**：`1/480`/`1/960` = **单次独立伯努利最终逐次概率（结算口径）**；`poi_yield.weight` = **批量开箱构成份额（统计口径，仅展示/统计）**，不做逐次门控。二者**串联**。见登记册 [B4] |
| **E2 ⚠️ 冲突** | 同上，`POI_DROP_SHIP_RATE = 1/960` | 同 E1 |
| E3 | 体力不足以完成一次探索（余 <6） | 按钮置灰 + tooltip「体力不足（需 6，余 N）」，**不允许透支**、不允许小数结算 |
| E4 | 当日槽位耗尽的岛 | 岛屿卡片显示「今日已探尽」，仍可进入（看情报、攻岛），只是无 POI 可打 |
| E5 | 玩家已拥有全部 20 卡，仍抽到 `crew` 槽 | 转为碎片（§6.4，×0.20 折算），**不空手** |
| E6 | 保底计数器与去重规则冲突（已满收集时保底无卡可给） | 满收集时保底计数器冻结，不再累计 |
| E7 | 跨日时点玩家正在探索中 | 结算以**请求到达时的 `seed_day`** 为准；跨日请求按新一日处理，槽位重刷、体力重置 |
| E8 | `boss` 型 POI 战斗失败 | 体力**已扣不退**，槽位**不消耗**（可用剩余体力再试）——避免"一次失败锁死当日 Boss 内容" |
| E9 | 玩家把 20 次体力全投在 FR_01（start，单槽 300） | 允许。日产 4×300=1,200 后无槽可打，剩余体力浪费——这是**玩家的错误决策**，UI 应在 §5.1 的期望值提示里预警，但不禁止 |
| E10 | 未占领岛的 POI 是否可打 | **可以**（`scouted` 即可）。占领只影响日产与维护费，不影响探索权——否则前期资源断流 |
