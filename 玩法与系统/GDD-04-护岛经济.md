## 1. 概述

护岛经济是 Demo 四闭环的**收束环**：探索（GDD-01）给一次性收入，战斗（GDD-03）给准入资格，占岛（GDD-02）给主权，而本系统把主权变成**持续现金流**，并用维护费把"持有"变成一个需要经营的决策。

**它在支柱体系中的位置**

| 支柱 | 本系统如何承载 |
|---|---|
| 支柱 1 · 一切可计算 | 日产 / 维护 / 净额三个数字在占岛前就能算出来，玩家能预判"这岛值不值得占" |
| 支柱 2 · 反制即协同 | 相邻加成让"占哪一片"成为拓扑决策，而不是"见岛就占" |
| 支柱 3 · 每天有明确进展 | 日产 + 连续投入制 = 每次上线都有可推进的进度条 |

**一句话设计意图**：护岛经济不是"占岛送钱"，而是**用一条随时间衰减的产出曲线，逼玩家不断向外扩张、向内升级**。

## 4. 机制

### 4.1 主循环

```
占岛（GDD-02）→ 岛进入 owned 集合
   ↓ 每日 0 点（链上：每次 claim 按经过天数补算）
产出 yield_i  ──┐
                ├──→ strategic 单池 ──→ sink（升级/开发/造船/维护）
维护 upkeep_i ──┘（强制先扣）
   ↓
净额为负的岛 = 玩家应主动放弃（Demo 无失守，故只体现在"不值得占"）
```

### 4.2 三个乘子的设计分工

| 乘子 | 玩家可控？ | 设计意图 | 若去掉会怎样 |
|---|---|---|---|
| `TIER_M` / `ISLAND_M`（档位/岛屿系数） | 否（选岛时确定） | 给"深入危险海域"数值理由 | 所有岛等价，海图退化成 12 个一样的按钮 |
| `dev_i`（开发度） | 是（投资源） | 主 sink，把"占岛"变成"经营" | 沉淀资源无处可去，池子暴涨 |
| `adj_owned_i`（相邻加成） | 是（选占领顺序） | 让占岛成为**拓扑题**而非清单题 | 占岛顺序无所谓，支柱 1 少一个可计算维度 |

### 4.3 时间衰减（本文新增，`econ31.py` 采用）

```
DECAY(k) = max(0.40, 1.0 − 0.06 × (k − 1))       k = 该岛在玩家占领序列中的名次
```

第 1 座岛 100% 产出，第 12 座 34%→ 截断到 40%。**意图**：让边际收益递减，防止"占满 12 岛"变成线性堆叠导致后期通胀失控。

> ⚠ **与 GDD-02 / 11 号文的差异**：那两份文档未引入时间衰减，改用 `UPKEEP_RATE=0.40` 比例维护费控制尾部。二者是**同一问题的两种解法**，不应同时全额启用。裁决建议见 §6.4。

### 4.4 维护费

```
upkeep_i = UPKEEP_BY_TIER[tier]        （本文：定值制）
   或
upkeep_i = yield_i × UPKEEP_RATE       （11 号文：比例制，UPKEEP_RATE = 0.40）
```

**定值制 vs 比例制**：定值制让"低产岛净额≈0、高产岛净额高"，强化选岛决策（支柱 1）；比例制对所有岛一视同仁，认知负担更低但决策空间更小。**本人倾向定值制**，理由见 §6.2 的净额表。

### 4.5 连续投入制（采纳 11 号文 §5.2 结论）

所有一次性 sink（升级 / 开发 / 造船）改为**进度投入制**：每个目标有 `need` 总额，玩家每日可投入任意额度累积 `progress`，投满即生效。

这是本次经济设计**最有效的单项修改**：它把脉冲式支出摊平为连续流，消除了"攒钱那几天池子暴涨、付款那天暴跌"的通胀锯齿。

## 6. 数值

### 6.1 护岛日产公式（**补齐 `islands.json` 缺失字段**）

```
yield_i = ISLAND_DAILY_YIELD × ISLAND_M[i] × (1 + DEV_STEP × dev_i)
                              × (1 + ADJ_BONUS × adj_owned_i) × DECAY(k)     [资源点/日]

ISLAND_DAILY_YIELD = 120          [资源点/日]  ← RULESET_LOCK §3 冻结，不改（索引见 数据层/constants.md）
DEV_STEP           = 0.25         [无量纲]     ← 新增 PLAYTEST_KNOB
ADJ_BONUS          = 0.10         [无量纲]     ← 新增 PLAYTEST_KNOB（GDD-02 §6.5 建议 0.25，见 §6.5）
DECAY(k)           = max(0.40, 1 − 0.06(k−1))  ← 新增 PLAYTEST_KNOB
ISLAND_M[i]        = 见下表        [无量纲]     ← 新增数据字段，缺省时回落到 TIER_M[tier]
TIER_M             = { start:0.5, light:1.0, heavy:2.5, boss:6.0 }
```

**`ISLAND_M` 不是我拍的数——它来自世界观圣经 §4.1 已有的每岛「专精产出 +N/天」**（G1 霜牙岛 寒铁 +10/天 …）。换算规则：

```
ISLAND_M[i] = 特产数量_i × RESOURCE_VALUE[特产种类] / ISLAND_DAILY_YIELD
RESOURCE_VALUE = { 寒铁:12, 鲸脂:12, 珍珠:12, 冰晶:20, 古老铭文:60 }   [资源点/单位]
```

校验：G1 霜牙岛 = 10 × 12 = **120** = `ISLAND_DAILY_YIELD` 基准 ✅ —— 冻结常量 120 从此有了世界观依据，而不是凭空的魔数。

### 6.2 净额结构（为什么用定值维护费）

| tier | 日产 | 维护 | 净额 | 净额率 | 设计语义 |
|---|---|---|---|---|---|
| start | 60 | 0 | +60 | 100% | 保底口粮，不可失 |
| light（最低 FR_02） | 96 | 50 | **+46** | 48% | **接近白占**——低产岛需要 dev 投资才划算 |
| light（最高 FR_10） | 200 | 50 | +150 | 75% | 优质岛，优先目标 |
| heavy | 300 | 175 | +125 | 42% | 高门槛高投入，回本慢 |
| boss | 720 | 500 | **+220** | 31% | **净额率全场最低**——Boss 岛的价值在 UR 掉落与叙事，不在现金流 |

> 比例制（`upkeep = yield × 0.40`）下所有岛净额率恒为 60%，上表这五行会塌成一行。**定值制是"选岛有得选"的数值来源**，建议采纳；若主理人认为认知负担过高，退回比例制 0.40，D5 仍达标（`11 号文 §5.3 表 C` 已验证）。

### 6.4 🔴 D5 峰值的结构性根因 = sink 断崖（`econ34.py` 假设检验）

**假设 H1**：峰值不是"产出太高"，而是"**一次性 sink 投满后，当日盈余无处可去**"。

**验证**（投入率 0.90，逐日看"当日总投入"与"日通胀"的关系）：

| 日 | 日通胀% | 当日总投入 | 池存 |
|---|---|---|---|
| 23 | 0.53 | 5,613 | 25,060 |
| 24 | 0.55 | 5,595 | 25,197 |
| 25 | **3.88** | **3,524**（造船投满，−37%） | 26,175 |
| 26 | **4.73 ← 峰值** | 4,366 | 27,413 |
| 30 | 3.57 | 4,978 | 31,416 |

**H1 成立** ✅：通胀跳变与 sink 容量断崖**同日发生**，与产出侧无关。

**修复 R1 · 新增可重复 sink「船体改装 refit」**：无总量上限、边际收益递减、吸收 85% 的剩余可支配盈余。

| 玩家日投入率 | 无 refit 峰值% | **有 refit 峰值%** | refit 累计 | D5 |
|---|---|---|---|---|
| 0.70 | 4.89 | 4.89 | 272 | ✅ |
| 0.80 | 4.00 | **3.32** | 3,224 | ✅ |
| 0.90 | 4.73 | **1.70** | 6,186 | ✅ |
| 1.00 | **6.58 ❌** | **0.98** | 9,143 | ✅ |

> 注意 `invest=1.00` 那一行：**不加 refit 时反而 FAIL（6.58%）**。因为全投入把池存压到 27,753，分母变小后同样的净流成了更高的百分比——这是滚动口径的**分母陷阱**。refit 把它压到 0.98%，**同时修好了 sink 断崖和分母陷阱**。
>
> **强烈建议把「船体改装」列入 Must**。它的成本是一个数值表 + 一个 UI 面板，收益是把 D5 的安全余量从 5% 提到 33%。

### 6.5 ✅ D5 在滚动口径下**依赖玩家行为** → 已决：锁定参考玩家档案（`econ33.py` / `econ34.py`）

> **【已决 · D1】** 主理人已拍板：**采用滚动口径 + 参考玩家档案**，固定分母口径废弃。
> ```
> REFERENCE_PLAYER = {
>     invest_rate: 0.80,
>     支出优先级: 维护费 > 主队升级 > 造船 > 岛屿开发 > 改装(refit)
> }
> ```
> **D5 硬断言** = 该档案下 30 日峰值日通胀 ≤ 5%。
> 复跑实测（`econ34.py`，`invest=0.80` + refit）：**3.32%**（`ADJ_BONUS=0.10`）/ **3.34%**（`ADJ_BONUS=0.25`，即已批 C-6 终值）→ **PASS，余量 33%**。
> 纯囤积玩家（`invest=0.00`，峰值 14.49% / 14.56%）**降级为监控指标**，不写进 D5 硬断言。

| 玩家日投入率 | 峰值日通胀% | 30 日末池 | D5 |
|---|---|---|---|
| 0.00（纯囤积） | 14.49 | 76,453 | ❌ |
| 0.20 | 11.98 | 65,172 | ❌ |
| 0.40 | 9.29 | 53,884 | ❌ |
| 0.60 | 6.40 | 42,593 | ❌ |

| 0.95 | 6.01 | 29,614 | ❌（分母陷阱） |
| 1.00 | 6.58 | 27,753 | ❌（分母陷阱） |

**纯囤积玩家在滚动口径下无法用 sink 救回**——实测两条路都堵死：

| 手段 | 强度扫描 | 纯囤积玩家峰值通胀 | 结论 |
|---|---|---|---|
| 维护费加倍 | ×1 → ×6 | 14.49% → 13.44% | ❌ 无效 |
| 囤积衰减 | 0.00 → 0.60 | 15.93% → 9.85% | ❌ 无效（但末池从 178,029 压到 31,097） |

**原因是数学的，不是配置的**：滚动通胀率 = 净流 ÷ 存量。玩家不花钱 → 净流 ≈ 全部产出 → 比率必然高。**任何 sink 都抓不到"不花钱的人"，只有产出侧闸门才行。**

> **已决（D1，主理人 2026-08-02 拍板）**：D5 验收锁定**参考玩家档案（reference player profile）**，而不是"任意玩家"。写入验收脚本：
>
> ```
> REFERENCE_PLAYER = { invest_rate: 0.80, 支出优先级: 维护费 > 主队升级 > 造船 > 岛屿开发 > 改装 }
> D5 判据 = 该档案下 30 日峰值日通胀 ≤ 5%     →  加 refit 后实测 3.32% ✅（余量 33%）
> ```
>
> 纯囤积玩家的 14.49% 降级为**监控指标**，在经济看板上作为"极端行为上界"跟踪，不作为验收门槛。理由：把不可控的玩家行为写进硬断言，等于让验收结果随机。

### 6.6 ✅ 两套通胀口径不一致 → 已决：统一为滚动口径（跨文档一致性）

> **【已决 · D1】** 主理人已拍板：**全项目统一采用滚动口径**（通胀率 = 当日净流 ÷ **前一日池存**）。
> `11 号文 §5.3` 的**固定分母口径（÷ 初始池 50,000）作废**，其 0.14% 读数不再作为 D5 依据，仅保留为历史记录。

本文与 `11 号文` 都跑了 D5，都 PASS，但**峰值差 33 倍**（4.70% vs 0.14%）。根因不是模型，是**分母定义**：

| | 本文 `econ31.py` | `11 号文 econ4.py` |
|---|---|---|
| 通胀率分母 | **前一日池存**（滚动） | **固定初始池 50,000** |
| 初始池 | 20,000 | 50,000 |
| 体力口径 | `POI=1` + 槽位充能 + 航行 8/跳 | `POI=6` |
| 尾部控制 | 时间衰减 `DECAY(k)` + 囤积衰减 10% | 比例维护费 0.40 + 软顶 60,000 |
| 峰值日通胀 | **4.70%** | **0.14%** |

**D5 断言原文只写"资源通胀率 ≤5%/天"，没有定义分母。** 这是 SSOT 的真实空缺，**已由主理人裁决补齐**。

> **裁决结果：采用滚动口径 + 参考玩家档案（§6.5），二者绑定生效。** 理由：固定分母会让通胀率随时间**自动趋近于 0**（分母恒定、后期净流又小），是个"越跑越好看"的指标，验收上没有约束力；滚动口径才真实反映"玩家手里的钱一天涨多少"。代价是它对玩家行为敏感——所以必须配 §6.5 的参考玩家档案才可用。**两者是一套组合，不能只取一半。**

**D5 验收口径（SSOT，写入验收脚本）**

```
日通胀率(d) = 净流(d) / 池存(d−1)          ← 滚动分母，不用固定初始池
D5 断言     = max{ 日通胀率(d) | d ∈ [1,30] } ≤ 5%
玩家档案     = REFERENCE_PLAYER（invest_rate=0.80，支出优先级见 §6.5）
终配实测     = 3.34%  ✅  PASS
监控指标     = invest_rate=0.00 时 14.56%（看板跟踪，不阻断验收）
```

### 6.8 `$TIDE` 分红（回应 A-08 / D5 第二断言）

```
tide_i = TIDE_BY_TIER[tier]     TIDE_BY_TIER = { start:0, light:1, heavy:3, boss:8 }   [枚/日]

## 7. 边界情况

| # | 边界 | 处理 |
|---|---|---|
| E1 | 玩家连续 N 天不上线，再上线一次性 claim | 链上按 `days = (now_height − last_claim) / BLOCKS_PER_DAY` 补算，**但 `DECAY(k)` 用 claim 时刻的占领名次**（名次不会因离线变化，安全）。设 `MAX_CLAIM_DAYS = 30` 截断，防止溢出与"挂机一年一次性倾泻" |
| E2 | 池存为负（维护费 > 收入） | **不允许负池**：池存不足时维护费按可支付比例扣，欠费岛进入 `arrears` 状态，日产降为 0 但**不失守**（Demo 无失守）。UI 必须红标，否则玩家不知道自己在白占 |
| E3 | 同一日既占岛又 claim | 占岛当日 `days = 0`，日产从**次日**起算。避免"占岛瞬间白拿一天"的刷分口子 |
| E4 | `dev_i` 投资过程中岛屿易主（P1+ 多人） | Demo 不发生。P1+ 规则预留：`dev` 随岛走不随人走（否则会诱发"喂岛"洗资源） |
| E5 | 囤积衰减与软顶同时触发 | 只取其一：先算软顶溢出，再对溢出部分施加衰减，**不叠乘**。否则超大池会被砍两次，出现悬崖 |
| E6 | `adj_owned_i` 在占岛瞬间双向变化 | 新占岛使**自己和所有相邻已占岛**同时获得加成，需一次性重算受影响岛集合，不能只算新岛（否则少发加成，玩家会发现账对不上） |
| E7 | 链上日（区块高度）与游戏内 0 点偏移（A-09） | 以**链上日**为唯一真源，UI 显示"下次可领取：约 N 区块后"，不显示自然时间。避免玩家按手机时间等到 0 点却领不到 |
| E8 | Boss 岛 FR_12 因 B3 打不过而始终无主 | `econ32.py` 实跑：峰值通胀 **4.73%**（与基线 4.73% 无差异），末池 31,236，**D5 仍 PASS** ✅。$TIDE 从 228 降到 212 枚。→ **D5 验收与 B3 是否解决完全解耦**，B3 延期不阻塞经济验收 |
| E9 | 玩家 100% 囤积（零投入） | `econ33.py` 实跑：峰值 **14.49%**（`ADJ=0.25` 下 14.56%），末池 76,453。**无法用 sink 修复**（维护费 ×6 → 13.44%；囤积衰减 0.60 → 9.85%）。处置：**已按 D1 裁决降级为监控指标**，不作为验收门槛，经济看板以"极端行为上界"跟踪。`HOARD_DECAY=0.10` 保留的理由是**压末池**（178,029 → 76,453，−57%），不是压峰值 |
| E10 | 玩家 100% 投入（零囤积） | 滚动口径下**同样 FAIL（6.58%）**——分母陷阱。加 §6.4 的 refit 可重复 sink 后降到 **0.98% PASS**。这是 refit 必须做的第二个理由 |
