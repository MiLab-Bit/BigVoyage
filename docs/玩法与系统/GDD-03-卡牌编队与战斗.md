## 1. 概述

战斗是 **auto-battle + 确定性纯函数**：`ResolveBattle(fleetA, fleetB, env, seed) -> {log, winner, hash}`。
玩家 100% 的策略表达发生在**点击出航之前**（编队构筑），战斗只把已决定的结果演出来。

三层约束共同构成构筑空间：`COST ≤ 10`、`槽位 ≤ 5`、`同体系 ≤ 4`。
**实测合法编队 11,653 种**（不含空队、不计顺序、无重复卡；分布：1 槽 20 / 2 槽 190 / 3 槽 1,112 / 4 槽 3,811 / 5 槽 6,520）。

> 与既有文档差异说明：此前文档记为 11,443，本次以 `verify.py` 穷举结果 **11,653** 为准。

## 4. 机制

### 4.1 回合结构（与代码实际行为对齐）

```
1. 初始化：全序排序（见 4.2）；env_mod 作用于 atk
2. 每回合：
   a. DoT tick（固定顺序 B 方先，A 方后 —— 不对称但确定，电路必须照抄）
   b. 按出手序，每单位结算一次主动（单段 or 多段）
   c. 控制判定 / 盾结算
3. 任一方 hp 全清 → winner = 存活方
4. 满 30 回合 → 按剩余总 hp 判定；**平局 HP 时 A 方胜**（非 draw）
```

### 4.2 排序全序（修正工程 BLK-4）

```
排序键 = (spd DESC, side ASC, slot_index ASC)
```
`cards.json` 中 spd 撞值概率高，必须显式全序，禁止依赖库排序稳定性。

### 4.3 伤害公式（单一真源，标单位）

```
DEF_COEF      = 0.30   ★已决 2026-08-02（护甲方案1）                [无量纲, 战斗常量, 进 ruleset_hash]
SEG_DECAY     = 0.40   ★已决 2026-08-02（D3）                      [无量纲, 战斗常量, 进 ruleset_hash]

armor_ratio   = target.def / (target.def + 100)              [无量纲, 0~1)
restraintCoef = 1.3 (克制) | 1/1.3 (被克) | 1.0 (无关)        [无量纲]
typeCoef      = TYPE_COEF[伤害类型][目标护甲类型]              [无量纲, 见 4.4]
envMod        = env_mod_for(sys)                             [无量纲, 见 4.6]
growthMult    = gm(level)                                    [无量纲, 见 GDD-02 养成轴, LVL_STEP=0.05]

# ① 有效攻击力（含环境 / 船体 / 养成）
eff_atk       = atk × envMod × shipAtkMod × growthMult                            [atk 点]

# ② 减法扣甲（★方案1：DEF_COEF 0.50 → 0.30，保持减法模型）
pierced_atk   = max(1, eff_atk − target.def × DEF_COEF)                           [atk 点]

# ③ 乘法减免 + 克制 / 类型 / 段衰减
单段伤害 dmg  = max(1, round( pierced_atk × restraintCoef × typeCoef
                              × (1 − armor_ratio) × SEG_DECAY^(k−1) ))            [HP 点]
                （k = 第几段，k=1 为首段，SEG_DECAY^0 = 1）

DoT 每跳      = max(1, round( baseAtk × dotRate × restraintCoef − target.def × DEF_COEF ))  [HP 点/回合]
真实伤害      = round( raw × restraintCoef )，单回合 ≤ maxHP × 0.08                [HP 点]
```

> ✅ **已决（2026-08-02，用户拍板）· 护甲公式 = 方案 1**：`DEF_COEF` 由 `0.50` 下调至 **`0.30`**，**保持减法模型**（不改除法）。
> 依据 `10-经济 §6.4`：`0.50` 下 R 卡对重甲靶的跨靶保值率仅 `0.071`、与 UR 的断层达 **9.7×**（8 张 R 卡在冻洋近乎完全失效）；
> `0.30` 把保值率抬到 **0.433**、断层压到 **1.7×**（实测 `_scratch/out_lock_a.txt`）。取"最小改动"路径，除法方案（原推荐案 3）留待 P1。
> ⚠ **`DEF_COEF` 是战斗常量，进 `ruleset_hash`**（`10-经济 §7.3` 红线 1）——写定后不可再变，直至链上电路冻结。
>
> ⚠ **本次落库同时消解了"文档 vs 代码不一致"，但方向与原建议相反，工程必须注意**：
> `战斗设计.md §7.4` 写 `− effectiveArmor`（**减法**），而 `ResolveBattle` v0.3 与全部仿真脚本
> （`verify6` / `bvd1_sim8` / `bv_engine`）**只有乘法减免、没有减法项**（等价 `DEF_COEF = 0`）。
> 本节原建议"保留代码的乘法语义"，**现被用户决策覆盖**：**减法项是唯一真源，工程需补实现**（上式 ②）。
> 这不是"改一个已存在的 0.5"，而是**新增一个此前未实装的计算级**，会改变全部守卫战胜率——实测见 §6.7。
> "多段应被护甲惩罚"的设计意图现由 ②（每段各扣一次甲）与 `SEG_DECAY` 段衰减**双重**承担。

### 4.4 TYPE_COEF 表（**补齐工程数据缺口**）

来源：`战斗设计.md §7.3`（constants.md 只写了"数值见战斗设计文档"，此处固化为可直接实现的表）。

| 伤害类型 \ 目标护甲 | 轻甲 light | 重甲 heavy | 能量盾 shield |
|---|---|---|---|
| 物理 physical（铁壁 / 疾风） | 1.00 | 0.70 | 1.15 |
| 燃烧 burn（烈焰） | 1.20 | 0.85 | 1.00 |
| 能量 energy（潮汐） | 1.10 | 0.80 | 0.60 |

体系 → 伤害类型映射：`flame→burn`、`ironwall→physical`、`wind→physical`、`tide→energy`。
定点化取值（SCALE=10000）：`{10000,7000,11500 / 12000,8500,10000 / 11000,8000,6000}`——全部是 2 位小数，定点无损。

### 4.5 克制环

`烈焰 → 铁壁 → 疾风 → 潮汐 → 烈焰`（顺环克制 ×1.3，逆环被克 ×1/1.3，对称环）。
**禁止预存 `1/1.3 = 7692`**：`13000 × 7692 / 10000² = 0.99996 ≠ 1`，会打破 SSOT §2.8 的对称环冻结口径。必须用除法 `dmg × SCALE / 13000`。

### 4.7 技能类型规格（**补齐 11/20 张卡技能未实装的设计规格**）

工程审计指出 `ResolveBattle` v0.3 仅实装 `dot` 与部分 `multi`，`armor`(5张)/`shield`(2张)/`control`(3张)/`buff`(1张) 无效果——
等于**铁壁与潮汐两个体系退化为白板属性**，支柱 2 不可被玩家感知。以下为可直接实现的规格：

| type | 卡数 | 结算时机 | 规格 | 护栏 |
|---|---|---|---|---|
| `armor` | 5 | 战斗开始（静态）/ 受击时（不破） | 修改目标 `effectiveArmor` 或 `defMod`，**乘算叠加**；铁砧卫自身 +30%、盾墙相邻 +10%、山岳全队 +15%、不破物理 −25%、要塞全队 +25% 且免疫 pierce | 全队 `def` 叠加后 ≤ `STAT_CAP.def = 200` |
| `shield` | 2 | 回合开始 | 生成 `shield_hp`，先于 `hp` 扣减；潮歌祭司=最低 hp 友军 `baseAtk×0.5`、渊主=全队 `baseAtk×0.6` | `MAX_SHIELD_MULT = 2.0`（盾 ≤ 本体 hp ×2） |
| `control` | 3 | 主动结算后 | `{prob, duration}`；被控单位跳过下 N 回合主动；渊鸣使全队 control `prob +10%`、`duration +1`；渊主 `prob +15%` | `MAX_STUN_ROUND = 3`（单目标累计，超则免疫） |
| `buff` | 1 | 战斗开始 | 火药坊：flame 体系友军 `atkMod +0.15`（加算） | 计入 `STAT_CAP.atk` |
| `dot` | 5 | 回合末统一 tick | `baseAtk × dotRate × restraintCoef`；同目标取 `max(旧, 新)` 非累加 | `MAX_DOT_STACK = 5` |
| `multi` | 5 | 主动结算 | 见 §6 修正案 | `MAX_EXTRA_HIT = 2` |

### 6.2 🔴 平衡红线 B2 · 疾风段数公式造成主导策略

**现象（`verify.py` / `verify2.py` 实测）**：
代码段数公式 `hits = 1 + clamp(spd//20 − 1, 0, 2)` 使 **5 张疾风卡全部恰好 3 段**，卡面声明的 2/2/2/3/4 段**全部失效**。

| 卡 | spd | 卡面段数 | 公式段数 | 一致？ |
|---|---|---|---|---|
| 信风斥候 | 65 | 2 | 3 | ❌ |
| 疾羽弓手 | 62 | 2 | 3 | ❌ |
| 疾风游骑 | 80 | 2 | 3 | ❌ |
| 长风破阵 | 95 | 3 | 3 | ✅ |
| 追风之翼 | 110 | 4 | 3 | ❌ |

**后果 —— 克制环被数值反转**：对冻洋守卫（ironwall / 重甲 / def=80）实测每 COST 效率：

| 体系 | 均值 效率/COST | 对守卫的克制关系 |
|---|---|---|
| **wind 疾风** | **36.4** | **被守卫克（×1/1.3）** |
| flame 烈焰 | 22.8 | 克守卫（×1.3） |
| tide 潮汐 | 16.7 | 无关 |
| ironwall 铁壁 | 14.8 | 无关（同体系） |

> **克制环有效性指数 = 克制方 ÷ 被克方 = 22.8 / 36.4 = 0.63**（应 > 1.00）。
> 即：**被克的体系反而比克制它的体系强 58%**。3 倍段数乘子完全压过 1.3 倍克制环。
> 最优编队为纯疾风 4 张（COST 恰好 10、槽 4、同体系恰好 4）——三重约束一个都没咬住。
> **支柱 2「反制即协同」在数学上已失效；支柱 1「可计算」退化为「算出来只有一个答案」。**

### 6.3 修正案对比（`verify3.py` 全量穷举）

| 方案 | 做法 | 克制环指数 | 体系极差 | 最优队体系分布 |
|---|---|---|---|---|
| 现状 | `1+clamp(spd//20−1,0,2)` | **0.63** ❌ | 2.45 | 疾风 ×4 |
| A | 段数取自卡面 | 0.73 ❌ | 2.11 | 疾风 ×4 + 烈焰 ×1 |
| B | 保留现段数 + 段衰减 0.6 | 0.95 ⚠ | 1.62 | 烈焰 ×2 + 疾风 ×2 |
| **C（推荐）** | **卡面段数 + 段衰减 0.40** | **双靶 1.10/1.04** ✅ | 2.18 | 烈焰 ×3 + 疾风 ×1 |
| D | 总攻预算制（atk×1.15 分 N 段） | 1.65 ⚠ 过矫 | 1.65 | 烈焰 ×4（疾风塌成 13.8/cost） |

**采用修正案 C**：

```
新增卡面字段 skill.hits_base（疾风：2/2/2/3/4，其余体系 = 1）
新增常量     SEG_DECAY = 0.40            [无量纲, PLAYTEST_KNOB]   # D3 终值（2026-08-02）：双靶复核通过区间 [0.05,0.43]，0.40 为兼顾多段伤害保留的采用值
段数 n = hits_base + clamp((spd − 100) / WIND_BONUS_SEGMENT, 0, MAX_EXTRA_HIT)
第 k 段伤害 = max(1, round(base_dmg × SEG_DECAY^(k−1)))     k = 1..n
```

**为什么是 C 而不是 D**：D 把疾风砍成全场最弱（13.8/cost），属于过度矫正——支柱 2 要求的是"每张卡都有天敌"，不是"抹平差异"。C 让疾风保持 21.8/cost（略低于烈焰 22.8），在**冻洋这个铁壁主场**被压制是**正确的**，换到其他海域（打潮汐守卫）疾风就该翻身。

**不动冻结常量**：`WIND_BONUS_SEGMENT = 20`、`MAX_EXTRA_HIT = 2` 均保持原值，只改**公式结构** + 新增一个 PLAYTEST_KNOB。风险最小。

**残留问题（如实说明）**：C 方案下体系极差仍为 1.54（>1.35 目标）。原因是本指标只测**进攻效率**，而铁壁（14.8）是坦克体系、潮汐（16.7）是控场体系，其价值在存活与控制，不在 DPR。待 §4.7 的 armor/shield/control 技能实装后需**重测综合胜率**，届时才是有效判据。

## 7. 边界情况

| # | 边界 | 处理 |
|---|---|---|
| E1 | 空编队 / 全部单位 COST 超限 | 编队校验层拦截，`ResolveBattle` 不接受非法输入（前置断言） |
| E2 | 双方同回合全灭 | `winner = "draw"`；占岛判定按**未占领**处理（挑战方不获得主权） |
| E3 | 满 30 回合未分胜负 | 按剩余总 hp 判；**HP 完全相等时 A 方（挑战方）胜** —— 与代码一致，但需在 UI 明示，否则玩家会认为是 bug |
| E4 | spd 完全相同 | 走 §4.2 全序 `(spd, side, slot_index)`，永不依赖库排序 |
| E5 | 单位 hp 被 DoT 与直击同回合打到 ≤0 | DoT 在回合末统一 tick，晚于主动；击杀归属 DoT 施加者 |
| E6 | 控制链导致某方全程无法行动 | `MAX_STUN_ROUND = 3` 累计上限后免疫；若仍全程罚站 → 30 回合按 HP 判 |
| E7 | 盾量 > 2× 本体 hp | `MAX_SHIELD_MULT = 2.0` 截断 |
| E8 | 伤害计算结果 < 1 | `max(1, ...)` 保底 1 点，**防止高护甲单位完全免疫** |
| E9 | 定点化后与浮点版结果分叉 | 见 A-02：**接受偏差，以定点版为唯一真源**；浮点版下线 |
| E10 | 同体系恰好 4 张（软上限边界） | 允许（`≤4`），第 5 张必须换体系 |
