## 第一章 听觉定位与四原则映射

### 1.1 听觉定位

**一句话定位**：音频是「沉没世界 → 秩序重建」史诗弧线的**隐形叙事层**——与美术讲同一个故事，不抢戏、不缺席、可复现。

三句功能定位（可验收）：

1. **听得懂（可读性）**：胜负、克制、combo 全部可听化——克制命中「克方音色凸显、被克方音色衰减」，玩家不看面板也能听出"这波为什么赢"（对齐 §13.3.2 + 规格层 §6.2 克制高亮）。
2. **记得住（辨识度）**：四体系签名音色 + 指挥官 Leitmotif 形成长期听觉记忆，抽到 C1 立即"拥有这个人的声音"（对齐 §13.3.5）。
3. **值得抽（仪式感）**：gacha 是主商业化（商业化统一设计 §1），仪式音是全游戏最高优先级反馈链之一，稀缺度越高仪式越长、越重、越不可跳过（§5.4）。

## 第二章 曲风与参考锚曲

### 2.1 曲风定义

**暗黑神话史诗 · 航海（Dark Mythological Epic · Nautical）**

- 调性语言：小调/多里安 = 沉没、未知；大调/利底亚 = 秩序、希望（§13.3.3）。
- 编制语言：真实管弦 + 合唱 + 管风琴，古典调式；允许合成器层做体系签名（烈焰 lead / 潮汐 pad），但主体是真实声学。
- 空间语言：物理空间混响（海浪、石厅、深渊），冷场景长混响、暖场景紧凑混响（§13.3.4）。
- 民间元素：船歌（shanty）/ 笛 / 鲁特琴等点缀，承担"航海、人类、烟火气"的暖色锚点，与神性压迫形成尺度反差。

### 2.3 回避清单

- 电子舞曲主导、纯钢琴曲风主导（可作点缀，不作主体）。
- 卡通/喜剧音效（与"神话写实"冲突，仅 UI 极轻反馈可用）。
- 无调性噪音堆砌（仅限恐怖/深渊短时点缀，不成段）。
- 文化混搭失控：三海领袖的民间元素必须归属各自海域（高加索=铁壁、亚特兰蒂斯=潮汐、中华=烈焰），不混用。

### 3.5 C1 变奏模板

C1 质变（§12.3：首抽即解锁核心机制/专属 combo）的听觉标识——**同一动机，变奏即质变**。模板：

## 第四章 音乐状态机

### 4.1 状态定义（intensity 0–3）

| intensity | 名称 | 内容 | 编制 | 典型场景 |
|---|---|---|---|---|
| 0 | 平静 | 仅环境层 bed（海域氛围：风/浪/船 creak/远鲸歌） | 稀疏（床+远声） | 菜单、港口、空旷海域、编队界面 |
| 1 | 紧张 | bed + 事件层轻（体系动机独奏/轻节奏组） | 中（动机+轻打击） | 读敌情、接近岛屿、敌情预警、编队博弈 |
| 2 | 战斗 | bed + 事件层全（体系动机+节奏组全量） | 中高（全节奏+动机） | 对局进行（单场 3–8 round） |
| 3 | 高潮 | 全编制 + 合唱 + 管风琴（叙事层叠加） | 高（全编制+神性） | combo 连发、决胜一击、世界 Boss、UR 入池、守卫王降临 |

### 4.2 状态转移条件

| 当前 → 目标 | 触发条件（确定性输入） | ramp 方式 | 时限 |
|---|---|---|---|
| 0 → 1 | 读敌情 / 接近岛屿 / 敌情预警（`sfx_nav_enemy`） | crossfade | 2s |
| 0 → 2 | 战斗开始（BattleLog 首个 `deploy`） | ramp 叠加 | ≤5s |
| 1 → 2 | 战斗开始（`deploy`） | ramp 叠加 | ≤5s |
| 2 → 3 | `combo_id` 触发 / `finisher` / UR 技能 | stinger 即时 + 层叠 | 即时 |
| 3 → 2 | combo 事件流结束 / 高潮回落 | crossfade 撤合唱 | 2s |
| 2 → 0 | `end` 事件（胜负结算） | ramp 回落 bed | ≤2s |
| 1 → 0 | 紧张解除（离开危险区） | crossfade | 2s |
| 任意 → 叙事 | 过场开始（`sfx_nar_cutscene_start`） | 硬切（叙事层接管） | 即时 |

### 4.3 量化同步点

- 网格：4/4 拍，BPM 随场景 90–120；以 **2-bar grid** 为默认量化步长。
- 非紧急转移（0↔1、1↔2）：等待到**小节起始**落 crossfade，避免拍点错位。
- 紧急事件（combo/决胜/克制凸显/敌袭 stinger）：**即时触发**，stinger 落点对齐事件 `t(ms)` 的下一 beat（±50ms 内）。
- 回放一致性：量化对齐基于事件流的绝对 `t(ms)` 轴，与玩家操作时刻无关——重放同 BattleLog 得到同一落点（研究权）。

### 4.4 ≤5s ramp 规格（呼应 §13.3.1 / §4.7 短平快）

进入战斗（0/1 → 2）声部淡入时间表：

| 声部 | 淡入起始 | 淡入完成 | 说明 |
|---|---|---|---|
| 节奏组（打击） | 0s | 0.5s | 先给"打起来了"的体感 |
| 体系动机（stems） | 0.5s | 1.5s | 按当前参战体系混合动机 |
| 全编制铺底 | 1.5s | ≤5s | 弦乐/铜管垫满 |
| **总 ramp** | 0s | **≤5s** | 硬上限 |

结束（2 → 0）声部淡出时间表：

| 声部 | 淡出起始 | 淡出完成 |
|---|---|---|
| 高音区（动机/lead） | 0s | 0.8s |
| 节奏组 | 0.8s | 1.5s |
| 全编制 → bed | 1.5s | **≤2s** |

### 4.5 stinger vs crossfade 决策

| 场景 | 方式 | 理由 |
|---|---|---|
| 状态平移（0→1→2、3→2、2→0） | crossfade ≤5s/2s | 平滑不打断，符合"短平快" |
| 突发事件（敌袭/风暴/Boss 警报） | stinger 即时 + 随后的 crossfade | 提示即时性优先 |
| combo/决胜/克制凸显 | stinger（即时，体系/Leitmotif 专属） | 反馈即时性 = 可读性 |
| 过场/章节/UR 入池/gacha 揭晓 | 硬切或专属 stinger + 叙事层 | 叙事/仪式接管 |
| 守卫王降临/先驱残响 | 全编制 stinger（合唱+管风琴） | 尺度反差最大化 |

### 4.6 确定性约束（红线①落地）

- 状态转移判定**只依赖确定性输入**：BattleLog 事件（`type/sys/restraints/combo_id/t(ms)`）+ 地图/编队状态；**不依赖音频内部随机**。
- 音乐层的变体/演奏抖动（如需）：由 `seed` 派生 PRNG 决定（§5.0 同源），同 BattleLog 同声。
- 音频层**零写回**结算：任何抖动、跳过、失败都不影响 `ResolveBattle` 输出与 hash 承诺。

### 5.0 总则

**命名约定**（评审路线图 §3.4 P0-① 锁定）：

| 分组 | 前缀 | 命名 | 说明 |
|---|---|---|---|
| 战斗 | `sfx_btl` | `sfx_btl_<type>_<sys>` | `type ∈ deploy/skill/hit/dot/control/combo/down/end` + 战斗辅助；`sys ∈ flame/ironwall/wind/tide` |
| UI | `sfx_ui` | `sfx_ui_<group>_<name>` | 界面反馈 |
| 海图/航海 | `sfx_nav` | `sfx_nav_<group>_<name>` | 海图/出航/环境物件 |
| gacha 仪式 | `sfx_gacha` | `sfx_gacha_<stage>_<rarity>` | 主付费点仪式 |
| 叙事 | `sfx_nar` | `sfx_nar_<name>` | 过场/Leitmotif stinger |

**优先级**：P0=上线必须（缺失即体验缺口）；P1=首版应含（事件槽位固定，素材可后补）；P2=增强（可降级/后置）。

**变体语义**：同一事件多版本素材；变体选择由 `seed` 派生 PRNG 决定（§4.6），同回放同选择。**音高/时长抖动幅度**：pitch ±50 cents、时长 ±5%（确定性 PRNG 产生，非 `Math.random`）。

**循环规则**：`无`=一次性 one-shot；`循环`=环境类长音，带进入/退出淡入淡出（淡入淡出 300ms）；`节拍内循环`=DoT 跳伤节拍锁定。

**同发上限**：见 §7.4；战斗 hit 类同发 ≤12。

**BattleLog 寄生映射**（红线①/规格层 §6.1 落地——音频层是 BattleLog 的**只读消费者**）：

| BattleEvent 字段 | SFX 消费方式 |
|---|---|
| `type` | 主事件映射（下表逐条） |
| `sys` | 选择体系音色族（`_<sys>` 后缀） |
| `restraints=true` | 叠加克方凸显 `sfx_btl_restraint_<sys>` + 被克方提示 `sfx_btl_restraint_hi` |
| `combo_id` | 叠加 combo 专属 stinger（火墙/锁定爆发/焚海连锁/海啸召唤） |
| `amount` | 命中轻重分层（轻/重/暴击力度曲线） |
| `t(ms)` | 调度时序：事件按 t 排序播放，回放时同一 t 同一声 |
| `seed` | 全部演出抖动唯一随机源（§4.6），绝不回流结算 |

1. **出现时机**（确定性触发）：该卡 `skill` 释放（UR/SSR 技能 stinger）→ `combo` 触发（C1 专属 combo）→ 叙事收口场景（S1「霜铁的誓约」过场：IRON_UR_01 动机 solo 定音鼓 → 全铁壁铜管，§13.3.5）→ gacha 揭晓（UR/SSR 揭晓 stinger）。
2. **变体选择**：由卡在队状态 + C1 状态 + BattleLog 事件决定，**无随机**；演奏微抖动用 seed 派生 PRNG。
3. **不串味**：Leitmotif 只归属其角色与体系；克制命中时克方 Leitmotif 可凸显，但被克方动机不得被"吃掉"（§3.2 衰减而非消失）。

### 6.3 C1 变奏规则（听觉资产感）

- **抽到 C1 = 立即拥有这个人的声音**（§13.3.5）：gacha C1 揭晓触发 `sfx_gacha_c1`（按体系选专属 stinger）。
- C1 变奏三处落地：①gacha 揭晓 ②战斗 combo 触发（如焚海连锁/海啸召唤）③卡面展示。
- 变奏维度模板见 §3.5；每条 C1 变奏 1–2s，录制/制作预算按卡池规模滚动（SSR/UR 优先，R 卡走通用模板）。

## 第七章 混音规范

### 7.1 总线树（A/B 双轨共用）

```
Master（母带）
├─ Music（音乐）
│   ├─ Bed          （环境层：海域氛围）
│   ├─ Stems        （事件层：体系动机+节奏组）
│   └─ Cutscene     （叙事层：线性管弦）
├─ SFX（音效）
│   ├─ Battle       （战斗，寄生 BattleLog）
│   ├─ Gacha        （抽卡仪式，主付费点）
│   ├─ UI           （界面）
│   └─ World        （海图/航海/物件 —— 唯一 3D 总线）
├─ Ambience（环境氛围）
│   ├─ Sea          （海域 bed：风/浪/鲸歌，随 env_bias 换滤镜）
│   └─ Zone         （岛屿/港口）
└─ VO（语音）
    ├─ Leader       （三海领袖）
    ├─ Compass      （罗盘旁白）
    └─ System       （系统播报/先驱/守卫王）
```

### 7.2 响度标准

| 项 | 移动端 | PC | 说明 |
|---|---|---|---|
| 综合响度（短时 LUFS，8s 窗） | **−16 LUFS** | **−18 LUFS** | 全场景一致，±0.5 LU |
| True Peak | ≤ **−1 dBTP** | ≤ −1 dBTP | 防削波/响度战争 |
| 采样率 | 48 kHz 全链 | 48 kHz 全链 | 统一防重采样开销 |

### 7.3 各总线相对电平与 ducking

| 总线 | 基准电平（相对 Master） | 动态规则 |
|---|---|---|
| Music.Bed | −6 dB | 常驻 |
| Music.Stems | +0 dB（叠加于 Bed） | 随 intensity 淡入淡出（§4.4） |
| Music.Cutscene | +2 dB | 叙事接管 |
| SFX.Battle | −3 dB（峰值 +0） | 战斗期间 duck Ambience −6 dB |
| SFX.Gacha | −6 dB（仪式时 +3） | 仪式期间 duck Music −9 dB + Ambience −6 dB |
| SFX.UI | −9 dB | 轻量，不抢戏 |
| SFX.World | −6 dB（3D 空间化） | 距离衰减线性 0–30 m |
| Ambience | −12 dB | 常驻底噪 |
| VO.Leader | −1.5 dB | 最高话语权 |
| VO.Compass | −3 dB | 旁白，略退 |
| VO.System | 0 dB（瞬时） | 播报 |

**Ducking 表**：

| 触发 | 被压总线 | 压量 | attack / hold / release |
|---|---|---|---|
| VO 播放 | Music（Bed+Stems） | −6 dB | 50ms / 200ms / 400ms |
| gacha 仪式全程 | Music | −9 dB | 100ms / 仪式时长 / 500ms |
| gacha 仪式全程 | Ambience | −6 dB | 100ms / 仪式时长 / 500ms |
| 战斗期间（intensity≥2） | Ambience | −6 dB | 50ms / — / 300ms |

### 7.4 同发上限与性能预算

| 项 | 移动端/Web | PC | 说明 |
|---|---|---|---|
| 战斗 hit 同发 | ≤12 voices | ≤12 voices | 防多段爆炸（疾风多段） |
| 总 SFX 同发 | ≤24 voices | ≤40 voices | 含 UI/World |
| 音乐 stem 同发 | ≤4（移动）/ ≤6（Web） | ≤8 | 降声部策略（§3.1） |
| VO 同发 | 1（排队） | 1（排队） | 永不叠话 |
| gacha 仪式同发 | ≤8 voices | ≤8 voices | 仪式密集但受限 |
| 音频常驻内存 | ≤256 MB | ≤512 MB | 长音乐/长 ambience 流式 |
| 码率 | 音乐 128 kbps（Ogg/Opus）/ SFX 96–128 / VO 64–96 | 音乐 192 kbps / 其余同上 | 移动端压缩优先 |

### 7.5 空间化/衰减

- **唯一 3D 总线 = SFX.World**（海图/航海物件）：Panner 空间化 + 距离衰减（线性 0–30 m），Web 轨用简化 HRTF（§9.3）。
- 战斗为 2D 演出（规格层 §6 锁定 2D）：无 3D 空间化，仅按 `row` 做立体声 pan（前/中/后 → −30% / 0 / +30%）。
- 混响：冷场景长混响（石厅/深渊 2.5–4s）、暖场景紧凑（港口/室内 1–1.5s）；A 轨用中间件 Reverb aux，B 轨用预渲染 IR（§9.3）。

### 8.3 本地化策略（出海 → 至少中/英）

- **首发双语言 VO 全量**：中文 + 英文（S1 三领袖 + 罗盘 + 先驱 + 系统播报；S2 守卫王）。出海为既定方向（评审路线图 G1 已决 = 仅出海），英文 VO 是出海底线，不是可选项。
- 其他语言（日/韩/西/葡…）：字幕本地化 + 关键角色 VO 可后补；**音乐与音效不本地化**（通用资产）。
- 流程：台词/字符串**冻结**（对齐叙事文档与本地化流水线）→ 双语配音排期 → 双轨打包（A 轨语言包 / B 轨按需下载）。
- 数量预算（首版）：三领袖各 ~50 句核心 + 罗盘 ~30 + 先驱 ~20 + 系统播报 ~40 条 × 2 语言。
- **合规**：出海市场须含英文 UI/VO 完整度；未成年人/区域合规由 release-ops 负责，音频侧只保证双语资产齐备。

### 8.4 VO 事件命名（并入事件清单风格）

VO 由音乐状态机与叙事系统调度，不单独建 SFX 事件表；接入点：`vo_<lang>_<char>_<lineId>` 作为事件名，触发点 = 过场脚本 / 战斗前摇 / gacha 结果语音（`sfx_gacha_reveal_ur` 可叠加角色 VO 一句）。VO 播放时按 §7.3 duck Music。

## 第九章 实现命名与交付规格（双轨）

### 9.1 共用真源（两轨唯一约束）

- **事件清单**（§5 全部 119 条）= 事件 ID 真源；A 轨 Wwise Event Name / FMOD Event Path、B 轨 dispatch key 必须与 ID 完全一致。
- **总线树**（§7.1）= 总线真源；A 轨 Bus Hierarchy、B 轨 GainNode 层级必须同名同构。
- **状态机**（§4）= 音乐状态真源；A 轨 State/RTPC、B 轨 JS 状态变量同一套 intensity 0–3 与转移表。
- **event_list.json**（§9.5 交付）为机读真源，两轨从同一文件生成工程绑定，杜绝漂移。

### 9.2 A 轨：Wwise/FMOD@Unity（引擎定案后启用）

**对象命名规范**：

| 对象 | 命名 | 示例 |
|---|---|---|
| Event | 事件 ID（§5） | `sfx_btl_hit_flame` / `sfx_gacha_reveal_ur` |
| Bus | 总线树同名（§7.1） | `Master/Music/Stems` |
| Switch Group | `Sys`（flame/ironwall/wind/tide）、`Rarity`、`Row` | `Sys=flame` |
| State | `MusicIntensity`（0–3） | `MusicIntensity=2` |
| RTPC | `BattleIntensity`、`DuckVO`、`SeedJitter`（0–1，seed 派生） | — |
| Game Object | `<card_id>`（单位）/ `BTL_<round>`（战斗） | `IRON_UR_01` |
| 互动音乐 | Wwise Interactive Music Hierarchy（Blend Container per intensity）/ FMOD 同构 | intensity 0–3 各一 Blend |

**策略**：战斗 SFX 用 Positioned/2D 混合（World 总线 3D，其余 2D）；克制凸显用 Switch(Sys) 选择凸显 bus 或 Event 内 layer；音乐 ramp 用 RTPC(BattleIntensity) 驱动 volume 曲线（对齐 §4.4 时间表）；确定性抖动用 RTPC(SeedJitter) + 变体容器（同 seed 同变体）。

**风险**：Wwise 无官方 Web runtime；FMOD HTML5 受限（streaming/性能）。若最终落 Web，A 轨工程不可直接复用 → 由 §9.4 降级方案承接。

### 9.3 B 轨：WebAudio@Web（链游/Web 落地的实现层）

**节点图（镜像总线树）**：

```
AudioContext（48kHz，用户手势后 resume）
└─ MasterGain
   ├─ MusicGain → BedGain / StemsGain / CutsceneGain
   ├─ SfxGain  → BattleGain / GachaGain / UiGain / WorldGain（PannerNode）
   ├─ AmbienceGain → SeaGain / ZoneGain
   └─ VoGain → LeaderGain / CompassGain / SystemGain
        （每总线一个 GainNode；空间化仅 WorldGain 挂 PannerNode；
          混响：Master 侧并联 ConvolverNode，预渲染 IR 2–3 个空间）
```

**策略**：
- 事件分发：事件 ID → 调度函数表（无中间件，自建轻量调度层，事件清单/总线树与 A 轨同源）。
- 音乐：多 stem 独立播放源（BufferSource 或 `<audio>` 流式）+ GainNode crossfade；状态机（intensity）在 JS 层实现，量化对齐用 `AudioContext.currentTime` 对齐 2-bar 网格（§4.3）。
- 变体：**预渲染多版本 buffer 池**（避免 playbackRate 变调的音质损失）；确定性抖动仍由 seed 派生 PRNG 决定。
- 混响：预渲染 IR + ConvolverNode（短 IR 控 CPU）。
- 空间化：仅 World 总线 PannerNode（简化 HRTF），战斗 2D 按 row 做 StereoPanner pan。
- 移动端/性能：AudioContext 需用户手势 resume（首音延迟 iOS 约 100–300ms）；预加载清单 + 分批 decode 控内存（§7.4）；多语言 VO 按需下载语言包。

**B 轨风险与降级（结论）**：事件清单/总线树 100% 共用不偏科；实现层降级集中在：①互动音乐平滑度（手动 crossfade，无 Wwise 平滑参数，≤5s ramp 仍可达但过渡略糙）②空间化（无反射/遮挡，仅简化 HRTF）③混响 CPU（短 IR）④首音延迟（iOS 手势解锁）⑤多语言内存（按需下载）。均有明确降级方案，**不阻塞双轨交付**；引擎定案后 A/B 只切实现层，事件与总线不动。

### 9.4 双轨风险对照

| 维度 | A 轨（Wwise/FMOD@Unity） | B 轨（WebAudio@Web） | 结论 |
|---|---|---|---|
| 互动音乐 | 原生 Interactive Music + State/RTPC | JS 状态机 + 手动 Gain crossfade | B 轨需自建调度层（~800 行） |
| 3D 空间化 | 原生 3D（Attenuation/Reflection） | 简化 HRTF（PannerNode） | B 轨降级：无反射/遮挡 |
| 混响 | Reverb aux 多空间 | 预渲染 IR（2–3 空间） | B 轨 CPU 受限用短 IR |
| 平台覆盖 | 无官方 Web runtime（Wwise）/ FMOD HTML5 受限 | 原生 Web/链游 | 若落 Web 只能 B 轨 |
| 移动端延迟 | 低（原生） | iOS 手势解锁 100–300ms | B 轨需预加载+手势引导 |
| 内存/码率 | 原生流式 | 按需下载语言包 | 共用 §7.4 预算 |

### 9.5 交付规格

**目录结构**（`assets/audio/`）：

```
assets/audio/
├── master/          # 源工程（DAW/Wwise/FMOD 工程，只读归档）
├── export/          # 按平台导出（unity_audio / web_audio）
├── music/           # 音乐素材（music_bed_<sea>_loop.ogg 等）
├── sfx/             # 音效素材（sfx_btl_hit_flame_01_v1.wav 等）
├── vo/              # 语音（vo_<lang>_<char>_<lineId>.wav）
├── event_list.json  # 机读事件清单真源（§5 全量，两轨消费）
└── bus_tree.json    # 机读总线树真源（§7.1 全量）
```

**文件命名**：`<事件ID>_<序号>_v<版本>.wav`（SFX）、`music_<层>_<场景>_<loop/one>.ogg`（音乐）、`vo_<lang>_<char>_<lineId>.wav`（VO）。

**版本与一致性**：音频资产（波形）**不参与 ruleset_hash**（不涉结算，链游红线①不触碰）；但 `event_list.json` / `bus_tree.json` 变更需走评审（影响两轨绑定），变更记入 CHANGELOG。

**验收清单（QA，对齐验收框架）**：
1. 响度：移动 −16 / PC −18 LUFS，True Peak ≤ −1 dBTP（全场抽测）。
2. 同发：战斗 hit ≤12、总 SFX ≤24/40、VO=1 不破。
3. **确定性**：同一 BattleLog + seed 回放两次，音频序列逐帧一致（红线①验收）。
4. 双轨覆盖：event_list.json 中全部事件在 A 轨 Event 与 B 轨 dispatch 表均有实现（覆盖率 100%）。
5. gacha：SSR/UR 揭晓、保底、C1 解锁、充值成功反馈全链路有声（主付费点验收）。
6. VO：中/英双语资产齐备、无叠话、duck 生效。
