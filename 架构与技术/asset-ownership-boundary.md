# BigVoyage · 资产确权边界方案

> 版本 v0.1 · 2026-08-02 · 作者：程基岩（engineering-lead）
> 决策记录：ADR-001
> **状态：基于现有初版数值假设定稿。§4「依赖数值模型的对齐假设」为待策划确认项，未确认前 §2 表格中标 ⚠ 的行不得进入实现。**

---

## 1. 划界三原则

| 原则 | 内容 | 反例 |
|---|---|---|
| **P1 稀缺性原则** | 只有**总量受限、可转让、有二级市场意义**的资产才上链 | 体力上限 120 但每日清空 → 不上链 |
| **P2 频率原则** | 状态变更频率 × 单次上链成本 = 不可接受时，留链下 + 定期承诺 | `strategic` 日产 20000，每次 POI 都变 → 链下 |
| **P3 争议性原则** | 会引发玩家间争议、需要第三方仲裁的状态，必须上链 | 岛屿归属（12 岛稀缺，必争）→ 上链 |

> 三原则冲突时优先级 **P3 > P1 > P2**。

> **船员卡私有是玩法资产，不只是隐私特性。**
> Aleo record 天然私有 ⇒ 对手看不见你的编队 ⇒ 弥补了 `seed` 不提供不可预测性的缺口（审计 BLK-3）。
> 「航海时代情报不对称」的叙事与 zk 隐私在这里天然同构，应作为比赛核心卖点。

## 3. 关键取舍：养成态放哪

这是确权边界里最容易做错的一处，单独说明。

**冲突**：卡牌是 NFT（可转让），但养成（升级/突破/命座 C6）是**高频操作**。

| 方案 | 做法 | 问题 |
|---|---|---|
| A. 养成态全链下 | record 只存 `card_id` | **致命**：二级市场买家无法验证卡的等级/命座，NFT 失去定价基础 |
| B. 养成态全链上，每次升级一笔交易 | record 存 level | 升 1 级 = 1 笔交易 + 1 次证明，体验灾难 |
| **C. 内嵌 + 批量提交（采用）** | record 存 level/breakthrough/constellation；链下先算，玩家在「返航/结算」时批量 re-mint | 链下与链上短暂不一致（UI 需标「未同步」） |

**采用 C**，并附两条实现约束：

1. **record 只存养成等级，不存推导属性。** 平衡性 patch（改 `cards.json` / `SKILL_SCORE_*`）不需要重铸全网卡牌。
2. **未同步的养成不生效于链上战斗。** 提交上链的战报，其编队属性以链上 record 的等级为准。
   避免"链下刷满级 → 打链上战斗 → 不同步"的作弊面。UI 必须明示这条规则。

## 4. ⚠ 依赖数值模型的对齐假设

> **本节是交叉评审重点。** 以下每条都是我在**没有策划确认**的情况下做的工作假设。
> 假设若被推翻，右列「影响面」中的架构决策需要返工。请策划成员（文策渊）逐条裁决。

| ID | 假设内容 | 我采用的取值 | 若被推翻的影响面 | 紧急度 |
|---|---|---|---|---|
| **A-01** | 链上「裁决战」可采用**降规格**，不必复用 30 回合 5v5 全规格 | `DUEL_SLOTS=3`、`DUEL_MAX_ROUND=8`、`MAX_EXTRA_HIT=1` | **最高影响**。若必须全规格上链，P2 全证明方案（~10⁶ 约束）不成立，需改走递归证明或彻底放弃 L3 | **P0 · 阻塞 ADR-003** |
| **A-02** | 定点化（SCALE=10000）引入的数值偏差**可接受**，允许因此微调平衡 | 十进制定点，`round_div` half-up；护甲比向下取整 | 若要求与现浮点版 **bit-exact** 一致，则定点化不可行 → 整条 zk 路线断裂（Leo 无浮点） | **P0 · 阻塞 BLK-1** |
| **A-03** | `STAT_CAP = {atk:200, def:200}`、`BOSS_HP = 5000` 是**永久上限**，不会因赛季膨胀 | 字段位宽按此定：atk/def `u16`，hp/伤害 `u32` | 若后续赛季突破上限 → record 结构变更 → 已铸卡牌需迁移（链上迁移代价极高） | 高 |
| **A-04** | `seed` **不影响**战斗结果这一现状是**可接受的设计**，不是待修 bug | 电路内不实现随机数；不可预测性靠 record 隐私提供 | 若 seed 需真正影响结果 → 电路需引入可验证随机 → 约束数与安全复杂度大幅上升 | 高 |
| **A-05** | **舰装（gear）不作为独立链上资产**，作为卡牌/旗舰的链下附属 | 舰装留链下 | 若舰装要可交易 → 新增 `Gear` record + 装备关系上链 → 编队合法性电路需同时验证舰装归属，约束翻倍 | 中 |
| **A-06** | 护岛日产可按 **每日 1 次 claim** 粒度结算，玩家接受"离线累积、上线领取" | 链上按 `(tier, 经过天数)` 重算 | 若要求实时到账/秒级累积 → 无法上链结算，`$TIDE` 净发行守恒失去链上强制点 | 中 |
| **A-07** | 岛屿日产公式为 `f(tier)` 的**纯函数**（仅依赖 tier 与天数），无玩家侧变量 | `islands.json` 目前只有 `tier` / `guard_hp`，**未定义日产字段** | 若日产依赖驻防编队/建筑等级/皮肤加成（`RESOURCE_SKIN_CAP_BONUS=0.30`）→ 链上无法独立重算，需额外承诺 | **高 · 数据缺口** |
| **A-08** | Demo 单池 `strategic`（日产 20000）**不上链**，只有兑换成 `$TIDE` 的部分上链 | 兑换口为唯一链上入口 | 若 strategic 本身要可交易 → 需第二个 token 程序 | 中 |
| **A-09** | `SOFT_TO_HARD_RATE=150`、`SOFT_EXCHANGE_DAILY_CAP=3` 的**日限**以链上区块高度为时间源，与游戏内"自然日 0 点"可存在偏移 | 用区块高度近似一日 | 若要求严格对齐 UTC+8 零点 → 需可信时间源，链上难做 | 中 |
| **A-10** | 岛屿总量 **Demo 12 / 全量 36** 是硬上限，且**每岛唯一归属** | `mapping u8 => address` | 多人环境下绝大多数玩家占不到岛 → 护岛经济对多数人失效。若改为多人共治/分服/岛屿分层 → 数据结构需重设计 | **高 · 玩法风险** |
| **A-11** | `cards.json` 卡牌 ID 可稳定映射为 `u16`，且**卡池只增不改**（不删除、不改已有卡的 system/rarity） | `card_id: u16` | 若已发行卡牌的 rarity/system 会被平衡性调整 → 影响 COST 计算 → 链上已铸 record 语义漂移 | 中 |
| **A-12** | 代码实际行为**优先于** `constants.md`：`MAX_STUN_ROUND` / `MAX_SHIELD_MULT` / `TRUE_DMG_*` 已冻结但**代码未实现**，电路以代码为准 | 电路不实现这三项 | 若这些机制要进战斗 → 电路规格需重估，约束数上升 | **高 · 文档与代码不一致** |
| **A-13** | POI 掉落可接受「探索即时给资源、**NFT 掉落每日 1 次批量结算**」，玩家不要求探索当下即时开箱 | 每日 1 笔 `daily_poi_draw` | 若要求即时开箱 → 只能退回中心化服务端签名（放弃去信任）或每次探索 1 笔链上交易（不可行） | **高 · 见补遗 01** |
| **A-14** | `poi_yield` 权重（crew 0.6 / ship 0.3 / crew_ur 0.05）与 `POI_DROP_CREW_RATE = 1/480` 的关系 | 暂按「1/480 为已含权重的最终概率」实现 | 两种读法发放量差异显著，直接影响 NFT 增发速率 | **高 · 数值口径缺口** |

### 4.1 需要策划补充的数据缺口

| 缺口 | 说明 |
|---|---|
| **岛屿日产数值未定义** | `islands.json` 只有 `tier` / `guard_hp` / `poi`，**没有日产字段**。而 D5 验收要求「跑 30 步资源通胀 ≤5%/天」——这个模拟当前无数据支撑。链上 claim 公式直接依赖此项（A-07） |
| **`TYPE_COEF` 表数值未给出** | `constants.md` 只说「数值写进代码常量；设计定义见《战斗设计》文档」。定点化与电路实现都需要具体数值 |
| **`env_mod_for()` 的完整映射** | 代码调用了 `GameData.env_mod_for(sys)`，`islands.json` 有 `season_mod: {ironwall:1.15, flame:0.95}`，`constants.md` 有 `ENV_BIAS_SEASON_ADVANCE`。三者关系需明确，且要进 `ruleset_hash` |
| **`ships.json` 缺失** | 代码读 `GameData.ships[ship_id]` 取 `atkMod/defMod/armorType`，但数据层没有该文件 |

## 5. 确权边界一览图

```
                        ┌──────── 上链（Aleo）────────┐
   稀缺 · 可转让 ────►   │  CrewCard record    [私有]  │
   争议 · 需仲裁         │  ShipBlueprint      [私有]  │
                        │  $TIDE token        [私有]  │
                        │  island_owner       [公开]  │
                        │  battle_commitment  [公开]  │
                        └────────────┬───────────────┘
                                     │ 兑换口 / claim 口
                                     │ （唯一受控通道，ADR-002）
                        ┌────────────┴───────────────┐
   高频 · 低价值 ────►   │  strategic 资源池           │
   无存量 · 无转让       │  琥珀币（SSOT 禁止上链）      │
                        │  体力（每日清空）             │
                        │  POI 记录 / 舰装 ⚠(A-05)    │
                        └──────── 链下 ──────────────┘
```
