## 1. MDA 框架分析

MDA = Mechanics（机制，设计师造什么）→ Dynamics（动态，运行时长出什么）→ Aesthetics（美学，玩家感受到什么）。
本作的设计难点在于：**战斗是纯 auto（玩家零操作）**，所以 Dynamics 层必须完全由「战前决策」驱动，否则 Aesthetics 会塌缩成「看数字掷骰子」。

### 1.1 Mechanics（机制层 · Demo 实装项）

| 机制 | 参数锚点 | 玩家可操作？ |
|---|---|---|
| 海图与相邻航行 | `数据层/adjacency.json` 12 岛邻接图 | ✅ 选目标岛 |
| 体力预算 | `STAMINA_MAX=120`，日刷清空 | ✅ 分配 |
| POI 探索与掉落 | `POI_RESOURCE_BASE=500`，crew `1/480`、ship `1/960` | ✅ 去/不去 |
| 编队构筑 | `FLEET_SLOTS=5` / `FLEET_CAPACITY=10` / `SAME_SYS_SOFT_CAP=4` | ✅ **核心** |
| 四体系克制环 | `RESTRAINT=1.3` / `RESTRAINT_DISADV=1/1.3` | ✅ 间接（选卡） |
| 伤害类型×护甲 | `TYPE_COEF` 3×3 | ✅ 间接（选船/选卡） |
| 环境偏置 | 冻洋 `ironwall 1.15 / flame 0.95` | ❌ 固定（Demo 单海） |
| 确定性结算 | `ResolveBattle(fleetA,fleetB,env,seed)` 纯函数 | ❌ 零操作 |
| 占岛与日产 | `ISLAND_DAILY_YIELD=120` | ✅ 占哪些岛 |

### 1.2 Dynamics（动态层 · 运行时涌现）

| 动态 | 由哪些机制交互产生 | 健康度 |
|---|---|---|
| **风险回报读盘** | 邻接图 + 守卫强度 + 体力预算 → 「先占边还是直扑 Boss」 | ✅ 成立 |
| **反制即协同** | 克制环 + 同队 combo → 克你的体系正是你该带的体系（火墙/锁定爆发） | ⚠️ **设计成立、代码未实装**（见 §1.4） |
| **COST 权衡** | COST≤10 × 槽≤5 × 同体系≤4 三重约束 → **11,653** 种合法编队（`verify.py` 穷举；此前记的 11,443 已作废） | ✅ 组合空间充足 |
| **体系轮换压力** | 冻洋 env_bias 偏铁壁 → 逼玩家用烈焰破局 | ✅ 成立 |
| **资源滚雪球** | 占岛日产 → 养成/造船 → 打更硬的岛 | ⚠️ Demo 缺养成环，雪球无出口（见 §1.4） |

### 1.3 Aesthetics（美学层 · 目标感受，按 LeBlanc 八分类）

主：**Challenge（挑战）**、**Discovery（发现）**、**Expression（表达）**
次：Fellowship（社交，P1+）、Narrative（叙事，框架预留）

| 美学目标 | 玩家原话（期望） | 支撑机制 |
|---|---|---|
| Challenge | 「这队我算过，能赢」 | 情报全透明 + 确定性结算 → 可计算而非可赌 |
| Discovery | 「渊眼那边到底有什么」 | 战略迷雾 + tier 分级 + Boss 岛 UR 偏向 |
| Expression | 「这是**我的**舰队」 | archetype 分工（非数值梯度）+ 11,653 组合空间 |

### 1.4 MDA 断点（本次分析发现的 3 处 M→D 传导失效）

> 这是本文最重要的产出：**机制层已设计但未传导到动态层**，会直接导致 Aesthetics 落空。

| # | 断点 | 现象（实测） | 影响的美学 | 修复归属 |
|---|---|---|---|---|
| **B1** | **11/20 张卡技能空转** | `ResolveBattle` v0.3 仅实装 `dot` 与部分 `multi`；`armor`(5张)/`shield`(2张)/`control`(3张)/`buff`(1张) 完全无效果 | Expression 塌缩——铁壁与潮汐两个体系退化为纯白板属性 | 工程（BV-Eng），设计规格见 GDD-03 §4 |
| **B2** | **疾风段数公式压平** | `hits=1+min(2, spd//20−1)` 使 5 张疾风卡**全部恰好 3 段**，卡面声明的 2/2/2/3/4 段全部失效 → cost1 疾风 R 卡输出 91/cost，是同 COST 铁壁卡的 **3.8 倍** | Challenge 塌缩——出现主导策略 | 设计（本文 GDD-03 §6 给修正公式）+ 工程 |
| **B3** | **Demo 缺养成轴，进度曲线断裂** | 全 20 卡满收集下 FR_12 渊眼**可胜编队 0 / 11,653**；FR_09 仅 1.3% | Discovery 断裂——Boss 岛不可达，D4 验收对 boss 岛不成立 | 设计（本文 GDD-02 §6 给三选一方案，待主理人拍板） |

## 2. 玩法支柱（3 条）

> 支柱 = 一切设计争议的裁决标准。任何新增内容若不服务于 ≥1 条支柱，或违反任一条，则不进 Demo。

### 支柱 1 · 「胜负在出航前决定」（Determinism before Departure）
玩家 100% 的策略表达发生在**点击出航之前**：读敌情 → 算克制 → 排编队。战斗只是把已决定的结果演出来。
- **推论**：必须情报全透明（无 fog），否则玩家无法计算，Challenge 变赌博。
- **推论**：战斗演出必须可读（克制高亮、伤害分解），否则玩家无法复盘，学习闭环断裂。
- **构筑深度验收轴（2026-08-06 三刀收口）**：**COST 分配 + UR 情境选择**（见 `玩法与系统/支柱收口-构筑UR克制.md` AC-C1/C2）。**禁止**用「上满 5 张 / 体系链」定义深度（[B6]）。
- **反例（禁止）**：任何战斗内实时操作、任何影响胜负的随机数（`seed` 仅可用于演出抖动）；满编激励工程。

### 支柱 2 · 「反制即协同」（Your Counter Is Your Combo）
克制环上克你的体系，同队时反而与你 combo（flame↔ironwall = 火墙；wind↔tide = 锁定爆发）。
- **推论**：任何一张卡都不能在所有 matchup 中占优——必须有天敌。
- **推论**：数值增长必须撞上 `STAT_CAP`，让后期养成转向机制而非碾压。
- **可感知门（2026-08-06 三刀收口）**：结算技能后果 + 对抗差 AC-R2/R3 + 战报可读 AC-R4/R5 必须同时成立；仅有环定义而无信号 = 支柱未落地。
- **反例（禁止）**：引入第五体系；任何「无视克制」的效果；同 COST 内存在严格 dominate 的卡（**B2 段数问题须按修正案 C 消除**）。

### 支柱 3 · 「航海是主轴，战斗是标点」（Voyage is the Sentence, Battle is the Punctuation）
玩家记忆点应是「那条高风险航线值不值」，而不是「那场战斗爽不爽」。战斗时长 ≤30s，占玩家在线时间 <20%。
- **推论**：资源与体力的**约束张力**必须真实存在，否则航海退化为无脑点击。
- **推论**：奖励重心放在 POI/占岛/日产，而非战斗直接掉落。
- **反例（禁止）**：为战斗加深度而拉长回合数；把资源产出的主要来源改为刷战斗。

## 3. 范围分层（Demo 切片）

> 与 SSOT §2.7 三层（全量愿景 / Demo / P0-P1-P2）对齐；本表是 **Demo 内部**的再分层，用于排优先级与砍量。

### 3.1 必须（Must · 缺任一则 Demo 闭环断裂）

| 项 | 对应 GDD | 验收锚点 | 当前状态 |
|---|---|---|---|
| 12 岛海图 + 邻接航行 + 迷雾 | GDD-01 | D1 罗盘指向 FR_01 | 数据已备 |
| POI 探索 + 体力扣减 + 掉落 | GDD-01 | D2 掉率可统计 | 数据已备 |
| 编队构筑三约束校验 | GDD-03 | COST≤10 / 槽≤5 / 同体系≤4 | 数据已备 |
| `ResolveBattle` 确定性 | GDD-03 | D3 同 seed 跑 100 次一致 | ✅ 已实现 |
| **20 卡技能全实装** | GDD-03 §4 | 4 体系均有可感知机制 | ❌ **B1 阻塞** |
| **疾风段数公式修正** | GDD-03 §6 | 同 COST 无 >60% 胜率卡 | ❌ **B2 阻塞** |
| 占岛 + 主权归属 + 日产累积 | GDD-02 / GDD-04 | D4 | 待实现 |
| 单池经济 30 步不崩 | GDD-04 | D5 通胀 ≤5%/天 | 待实现 |
| **进度曲线可通关**（FR_12 可达） | GDD-02 §6 | 存在合法路径打穿 Boss | ❌ **B3 阻塞，待拍板** |

### 3.2 应有（Should · 缺失则体验残缺但闭环成立）

| 项 | 理由 |
|---|---|
| 战斗日志克制高亮 + 伤害分解 | 支柱 1 的学习闭环；缺则玩家不知为何输 |
| 编队预测仪表盘（克制 +X%/被克 −Y%、combo 提示） | 支柱 1；纯 auto 下玩家唯一信息优势来源 |
| 岛屿 tier 与实际难度对齐（守卫 HP 审计修正） | 见 GDD-02 §6；当前同 tier 难度极差 2.03x |
| 航线风险分级（顺流/截直/远海 R=1/2/3） | 支柱 3 的核心张力来源 |
| 卡面 `strong_against`/`countered_by` 常驻显示 | diegetic 教学，降低认知负荷 |

### 3.3 可有（Could · Demo 可砍，不影响验收）

| 项 | 砍掉的代价 |
|---|---|
| 航行随机事件（遇难商船/海怪/遗迹等 5 类） | 探索重复度上升，但闭环完整 |
| 位序双轴（前中后 row × speed_order） | 编队从 2D 降为 1D，组合空间仍有 11,653 |
| 多指令优先级列表 Directives[] | 编队表达变浅，但核心权衡仍在 |
| 叙事碎片与图鉴进度 | 长线目标感缺失，Demo 期可接受 |
| 赛季日历 / UP 池 / gacha UI | Demo 明确 Non-Goal（SSOT §2.7） |

### 3.4 明确不做（Non-Goals · 沿用 Demo 契约 §3，不重复论证）
三海域 36 岛 / 真 Aleo 链 / 三赛季叙事 / gacha 概率合规与真支付 / 贸易·科技·联盟·跨海深度 / 商业护栏常量改动。

## 4. 系统依赖排序（工程实现顺序建议）

```
        ┌─────────────────────────────────────────┐
        │  GDD-03 卡牌编队战斗（战斗核）           │  ← 最底层，其余三系统都调用
        │  ResolveBattle 纯函数 + 20 卡技能        │
        └───────────────┬─────────────────────────┘
                        │ 提供 winner/log/hash
        ┌───────────────▼─────────────────────────┐
        │  GDD-01 探索 POI（海图/航行/体力/掉落）  │  ← 产出资源与卡，喂给战斗
        └───────────────┬─────────────────────────┘
                        │ 提供「已抵达岛屿」
        ┌───────────────▼─────────────────────────┐
        │  GDD-02 占岛护岛（守卫战/主权/护岛者）    │  ← 消费战斗结果，产生岛主权
        └───────────────┬─────────────────────────┘
                        │ 提供「已占岛列表」
        ┌───────────────▼─────────────────────────┐
        │  GDD-04 护岛经济（日产/单池/通胀控制）    │  ← 最上层，依赖前三者
        └─────────────────────────────────────────┘
```

**关键路径**：GDD-03 的 B1/B2 修复是全项目最高优先级——它同时阻塞 D3（战斗确定性验收的**意义**）、GDD-02 的难度曲线、GDD-04 的日产校准（打不过岛就没有日产）。

**可并行**：GDD-01 的海图/航行/体力 UI 与 GDD-03 的技能实装无依赖，可并行开发。
