## 1. 闭环全景

```
                    链下高频层（Godot 本地）
   ┌───────────────────────────────────────────────────────┐
   │  体力(120/日清空) ──► POI 探索 ──► strategic 资源池      │

        ┌───────────▼──────────┐   ┌───────────▼────────────┐
        │  闸门 A · 占岛确权     │   │  闸门 B · 软→硬兑换      │
        │  claim_island()      │   │  150 琥珀 → 1 $TIDE     │

   │      │                                                │
   │      ├──► gacha（主商业化，160 晶/抽）──► CrewCard record │
   │      ├──► market_fee（交易税，burn）                     │
```

> ⚠ **v0.1 修订**：补遗 01 新增**闸门 D · POI 掉落抽取**（`daily_poi_draw` + `claim_poi_drop`），
> 承载链下探索 → 链上 NFT 铸造。跨层通道由 3 个增至 **4 个**。详见 `addendum-01-verifiable-randomness.md`。

**这些闸门是链上↔链下的全部通道。** 除此之外不存在任何跨层价值流动——
这条约束让经济审计面收敛到 4 个函数，是整个设计最重要的性质。

## 2. 闸门规格

### 闸门 A · 占岛确权

```
输入：island_id, battle_commitment, (P1) 编队 record + 合法性证明
链上校验：
  1. island_owner[island_id] 为空 或 满足挑战条件
  2. battle_record[commitment] 存在且 winner == 挑战方
  3. (P1) 编队合法性证明通过（COST≤10 / 槽≤5 / 同体系≤4 / 卡牌归属）
效果：
  island_owner[island_id] = caller
  island_claimed_at[island_id] = block.height
```

**冲突解决**：多人同时 claim 同一岛 → 链上交易顺序决定，后到者 revert。
无需额外锁机制——这正是把归属放链上的核心价值。

### 闸门 B · 软→硬兑换

```
SOFT_TO_HARD_RATE = 150      // 150 琥珀币 = 1 $TIDE
SOFT_EXCHANGE_DAILY_CAP = 3  // 每日 ≤3 $TIDE，即 450 琥珀 sink
方向：单向。反向（$TIDE → 琥珀）永久关闭 —— SSOT 已冻结，防双向套利通胀
```

**工程难点**：琥珀币在**链下**，链上无法验证玩家真有 450 琥珀。

三个选项：

| 方案 | 做法 | 评价 |
|---|---|---|
| B1 · 服务端签名 | 链下服务端核验余额后签名授权 | 引入中心化信任，与 zk 叙事矛盾 |
| B2 · 琥珀币也上链 | 违反 SSOT「不链上流通」冻结口径 | 否决 |
| **B3 · 日限即上限（采用）** | 链上**只强制日限 3**，不验证琥珀余额；链下扣琥珀 | 最坏情况：玩家绕过客户端白嫖 3 $TIDE/日。用日限把损失封顶，且该额度本就是设计发放量 |

**采用 B3**：把「无法验证」转化为「有界损失」。日限 3 是硬天花板，即使 100% 玩家作弊，
增发量也等于设计上限，`net_issuance ≤ 0` 的总护栏依然成立。
> 这是一个刻意的取舍：**用经济护栏兜住技术上无法验证的部分**，而不是为了可验证性把琥珀币拖上链。

### 闸门 C · 护岛日产领取

```
输入：island_id
链上校验：
  1. island_owner[island_id] == caller
  2. current_height - last_claim_height[(caller, island_id)] ≥ BLOCKS_PER_DAY
效果：
  days = (current_height - max(claimed_at, last_claim)) / BLOCKS_PER_DAY
  amount = yield_by_tier[tier] × days      ⚠ 依赖 A-07：日产公式必须是 tier 的纯函数
  mint $TIDE(amount) 且断言 total_minted ≤ total_burned + genesis
  last_claim_height = current_height
```

⚠ **数据缺口**：`islands.json` **当前没有日产字段**（只有 `tier`/`guard_hp`/`poi`）。
`yield_by_tier` 需策划补齐，否则闸门 C 无法实现。已列为确权文档 §4.1 首要缺口。

## 3. `net_issuance ≤ 0` 的链上强制

`resources.json` 写明 `$TIDE` 的 `net_issuance: "<=0"`。这条经济红线**不能只靠数值表自觉**。

```leo
mapping supply: u8 => Supply;   // {minted: u64, burned: u64, genesis: u64}

// 任何 mint 路径（闸门 B / C）末尾统一断言：
assert(supply.minted <= supply.burned + supply.genesis);
```

**后果**：当全服 burn（gacha 消耗 + market_fee）不足时，**mint 会失败**——
玩家领不到日产。这在链上是"交易 revert"，在玩法上是"潮汐退去，海域贫瘠"。

**这是设计特性不是 bug**：把通缩压力做成可感知的世界状态，玩家会自发去消耗 $TIDE 以恢复产出。
但需要策划确认这个体验是否可接受（→ 与经济模型 D5「跑 30 步不崩」联动验证）。

**建议缓冲机制**：设 `genesis_supply` 为一个赛季预算池，避免开服即枯竭；
赛季结算（SEASON_DAYS=90 的 D85–90）时重置，与赛季叙事对齐。

## 4. 反作弊：作弊 = 无法生成有效证明

### 4.1 作弊面盘点与防线映射

| # | 作弊手段 | 门槛 | 防线 | 阶段 |
|---|---|---|---|---|
| 1 | **凭空造牌**（改存档给自己 UR 卡） | 极低（改 JSON） | **L2 · record 所有权**——卡只能由 program mint，改客户端无法伪造 record | P1 |
| 2 | **超 COST 编队**（5 张 UR = COST 20） | 极低 | **L2 · 电路断言** `Σ COST_BY_RARITY ≤ 10`、槽≤5、同体系≤4 | P1 |
| 3 | **篡改战报**（改 winner 后提交） | 低 | **L1 · 承诺绑定**——commitment 绑定 winner，改 winner 则 hash 不匹配 ⚠ **当前实现有洞，见审计 BLK-2** | P0 |
| 4 | **重放战报**（同一场胜利反复占岛） | 低 | commitment 唯一性 mapping + `island_claimed_at` | P1 |
| 5 | **伪造自洽战报**（构造一份符合规则但没真打的日志） | **高**（需完整逆向规则引擎） | **L3 · 全证明**（P2）或 **挑战期欺诈证明**（P1.5） | P1.5/P2 |
| 6 | **刷 POI 掉落**（穷举 `seed_day` 刷 1/480 NFT） | **极低**（本地跑自己的代码穷举即可） | **闸门 D · 每日批量链上 `ChaCha` 抽取**，票数 `≤ STAMINA_MAX = 120` 硬上限 ⇒ 谎报上限 = 诚实上限。详见 `addendum-01-verifiable-randomness.md` | P1 |
| 7 | **链下刷养成后上链** | 中 | 链上战斗以 record 内养成等级为准（确权文档 §3 约束 2） | P1 |
| 8 | **白嫖软硬兑换** | 低 | 闸门 B3：不验证，用日限 3 封顶损失 | P1 |
| 9 | **重复领日产** | 低 | `last_claim_height` mapping | P1 |

### 4.2 关键洞察：优先级不是按"严重度"排，是按"门槛 ÷ 防御成本"排

```
作弊 #1/#2（凭空造牌、超编队）
    门槛：极低（记事本改 JSON）
    防御成本：~3k 约束
    → 性价比极高，必须优先

作弊 #5（伪造自洽战报）
    门槛：极高（要完整复刻定点规则引擎、900 条日志自洽）
    防御成本：66k~1M 约束
    → 性价比低，可延后 / 用挑战期替代
```

**结论：先做 L2（输入证明），不要一上来追求 L3（全证明）。**
这也是 `aleo-onchain-architecture.md` §2 的核心判断。

### 4.3 挑战期机制（P1.5，L3 的低成本替代）

```
提交承诺 ──► [挑战窗口 N 区块] ──► 无人挑战 → 最终确认
                   │
                   ├── 有人质押挑战 ──► 被挑战方须在窗口内提交
                   │                    Merkle 局部开示 / 完整证明
                   │                         │
                   │              ┌──────────┴──────────┐
                   │              ▼                     ▼
                   │        证明有效                 未提交/无效
                   │        挑战者失去质押           占岛回滚
                   │                                挑战者获赔
```

**博弈性质**：只要挑战有利可图且任何人可挑战，作弊的期望收益为负——
即使实际几乎没人挑战。**用博弈论换约束数**，这是乐观验证的核心价值。

**代价**：占岛不是即时终局的，有 N 区块的"结算中"状态。
如 `aleo-onchain-architecture.md` §5.2 所述，这个延迟应包装成航海叙事（消息随船传回），而非 loading。

### 4.4 叙事收口

> **「作弊 = 无法生成有效证明」不是口号，需要落到具体防线才成立。**
> 严格地说，P1 阶段成立的命题是：
> **「使用你不拥有的卡牌、或违反编队规则 = 无法生成有效证明」**。
> 而「伪造战斗过程」要到 P1.5（经济上不划算）/ P2（密码学上不可能）才封死。
> 对外叙事建议**如实分层表述**，不要宣称 P0 的哈希 mock 就等于反作弊——
> 评委大概率会追问这一点，诚实分层反而是加分项。

## 5. 与 D5 验收的衔接

Demo 契约 D5：**「跑 30 步，资源通胀率 ≤5%/天，$TIDE 净发行 ≤0」**

链上化后 D5 需扩展为**双账本对账**：

| 断言 | 链下 | 链上 |
|---|---|---|
| 资源通胀 ≤5%/天 | `strategic` 池模拟 | — |
| `$TIDE` 净发行 ≤0 | 模拟器统计 | `supply.minted ≤ supply.burned + genesis` 链上断言 |
| **双账本一致** | 链下预测的 claim 总量 | 链上实际 mint 总量 | 
| 闸门 B 上限 | — | 全服 mint ≤ 玩家数 × 3/日 |

**建议**：经济模拟器（策划侧）与链上 mapping 状态做**逐日对账测试**，
任何一天出现偏差即为规则实现不一致。这是链下经济模型与链上强制的交叉验证点。

> ⚠ 当前 SSOT 的经济压测是 **30 步压缩模型**，而正式赛季 `SEASON_DAYS = 90`。
> 链上 `genesis_supply` 的容量必须按 **90 天**外推设定，不能直接用 30 步结论。
