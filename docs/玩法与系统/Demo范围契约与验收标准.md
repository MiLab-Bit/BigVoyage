> 目的：解决 review #3（文档范围与技术架构阶段 A 矛盾），给 AI 一个**不可越界的切片**，避免摊大饼。  
> **SSOT**：数值见 `数据层/constants.md`；跨文档冲突见根目录 `00-口径冻结表_SSOT.md`（**v1.1 矛盾裁决已冻结**）。

> **范围纪律**：玩法圣经「10 项子玩法」= 全量**设计愿景**；本文件 = **工程首切片**。二者冲突时以本文件为准。  
> 配套：战斗设计.md / 数据层/*

## 2. 核心 4 系统闭环（验收对象）

1. **POI 探索**：顺流靠岛 → 消耗体力 → 得资源/卡（D2）
2. **占岛护岛者**：击败 PVE 守卫 → 岛主权归属 → 护岛者产出累积（D4）
3. **卡牌战斗**：组队(≤COST) → `ResolveBattle` 纯函数结算 → deterministic winner（D3）
4. **护岛者经济**：占岛后产出流入单池，跑 30 步不崩（D5）

---

## 3. Non-Goals（显式"不要做"，给 AI 画边界）

- 不做 36 岛三海域全经济
- 不接真 Aleo 链
- 不做 3 赛季完整叙事
- 不做 gacha 概率合规微调 / 真支付
- 不深度做贸易/科技/联盟/跨海/Boss（仅入口桩）
- 不碰商业护栏常量（`RESTRAINT=1.3`、`STAT_CAP`、保底 70/140 等锁死；见口径冻结表）
- 不把玩法圣经「10 项愿景」当成 Demo 必做清单

AI 越界任一项即判定 demo 失败。

## 4. 用户故事验收表（D1–D5）

| ID | 用户故事 | 可测断言（自动化） |
|---|---|---|
| D1 | 选海域建号 | 进入单海地图，罗盘指向最近岛（FR_01） |
| D2 | 顺流靠岛 + 打 POI | 消耗 1 体力，得资源/卡；NFT 掉落概率命中可统计（crew 1/480, ship 1/960） |
| D3 | 组队打守卫 | 输入两 fleet + env + seed，纯函数输出 deterministic winner（同输入同输出，跑 100 次一致） |
| D4 | 占岛 | 击败 PVE 守卫后岛主权归属当前玩家，护岛者产出开始累积 |
| D5 | 经济不崩 | 跑 30 步，资源通胀率 ≤5%/天，$TIDE 净发行 ≤0 |

> 验收脚本建议：用 `ResolveBattle` 跑 100 次相同 seed 验证 D3 确定性；用经济模拟跑 30 步验证 D5。详见数据层常量。
