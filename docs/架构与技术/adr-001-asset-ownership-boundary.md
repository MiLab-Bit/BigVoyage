# ADR-001 · 资产确权边界

- **状态**：Proposed（待主理人 + 策划交叉评审）
- **日期**：2026-08-02
- **决策人**：程基岩（engineering-lead）
- **相关**：`asset-ownership-boundary.md`、ADR-002、ADR-003

---

## 1. 上下文

BigVoyage 要上 Aleo，必须先回答「什么东西上链」。约束条件：

- Aleo 有两种状态载体：**record**（私有、UTXO 模型、玩家本地持有）与 **mapping**（公开、全网可见）。
- SSOT v1.1 已冻结部分口径：琥珀币「不可直购、不链上流通」；`$TIDE` = 航海晶，`net_issuance ≤ 0`；船员卡/船图纸标注 `type: nft`。
- 上链有真实成本：交易 fee、证明生成时间（秒~分钟级）、状态变更延迟。
- 数值模型仍是初版：`islands.json` 没有日产字段，`ships.json` 缺失，`TYPE_COEF` 未给数值。
- 岛屿是**全局稀缺**资源：Demo 12 个、全量 36 个。

若边界划错，代价不对称：**上链上多了** → 体验崩坏、fee 爆炸、改不动（链上数据迁移极贵）；
**上链上少了** → 资产无法交易，链游叙事不成立。

---

## 2. 备选方案

### 方案 A · 全链上（Fully On-Chain Game）

所有状态（含体力、资源池、POI 记录）都上链。

- ✅ 叙事最纯粹，最"链游"
- ❌ 体力每日清空、资源日产 20000 —— 高频写入，fee 不可承受
- ❌ 每个操作都要等证明 + 出块，SLG 的操作密度完全无法支撑
- ❌ 与 SSOT「琥珀币不链上流通」直接冲突

### 方案 B · 全链下 + 单一存档哈希上链

只把整个存档的哈希定期上链。

- ✅ 实现最简单，接近现状 `CHAIN_MOCK`
- ❌ 只能防"事后篡改"，防不了"一开始就是假的"
- ❌ 资产无法 P2P 转让（哈希不是资产），无二级市场
- ❌ 拿不到 Aleo record 的隐私能力 —— 白白浪费本项目最契合的技术特性

### 方案 C · 按「稀缺性 / 频率 / 争议性」三原则分层（采用）

稀缺可转让 → record；争议需仲裁 → mapping；高频低价值 → 链下；养成态 → 内嵌 record + 批量提交。

- ✅ 与 SSOT 已冻结口径完全兼容，无需推翻策划决策
- ✅ 船员卡用 record（私有）→ 编队隐藏成为玩法，弥补 `seed` 不提供随机性的缺口（审计 BLK-3）
- ✅ 岛屿用 mapping（公开）→ 海图可显示归属，多人抢岛冲突由链上顺序自然解决
- ✅ 跨层通道收敛到 3 个闸门，经济审计面极小
- ❌ 存在链下↔链上短暂不一致窗口，UI 需明示「未同步」状态
- ❌ 养成 re-mint 有额外交易成本

### 方案 D · 全部资产上链但用侧链/L2 降本

- ❌ Aleo 生态当前无成熟 L2；引入额外信任假设；比赛叙事应聚焦 Aleo 本身
- ❌ 超出比赛周期可承受的工程量

---

## 3. 决定

**采用方案 C。**

上链确权：`CrewCard`(record/私有)、`ShipBlueprint`(record/私有)、`$TIDE`(record + 供应量 mapping)、
`island_owner`(mapping/公开)、`battle_commitment`(mapping/公开)、`island_claimed_at`(mapping/公开)。

链下：琥珀币、`strategic` 资源池、体力、POI 记录、卡牌推导属性、舰装（⚠ A-05 待确认）。

配套两条硬约束：

1. **record 只存养成等级，不存推导属性** —— 平衡性 patch 不需重铸全网卡牌。
2. **未同步的链下养成不生效于链上战斗** —— 封死"链下刷满级"作弊面。

## 4. 后果

### 正面

- 船员卡私有性把「zk 隐私」和「航海时代情报不对称」缝成同一件事，是最强的比赛叙事资产。
- 岛屿归属上链 = 天然的多人冲突仲裁，不需要自建权威服务器。
- 3 个闸门的收敛结构，让 ADR-002 的经济护栏有明确落点。
- 边界与 SSOT 已冻结口径零冲突，不需要策划返工。

### 负面 / 需承担

- **链下链上不一致窗口**：UI 必须有明确的「已确权 / 结算中 / 未同步」三态设计（需美术与 UX 配合）。
- **养成 re-mint 成本**：需批量化，且要设计"多久提交一次"的默认策略。
- **岛屿稀缺性风险（A-10）**：36 岛 vs 玩家数，多人环境下绝大多数玩家占不到岛，护岛经济对他们失效。**这是玩法问题不是技术问题**，需在多人化前由策划解决。
- **字段位宽锁定（A-03）**：atk/def `u16` 基于 `STAT_CAP=200` 永不上调的假设。若后续赛季膨胀数值，链上已铸 record 迁移代价极高。
- **A-01/A-02 未确认前，本 ADR 的实现不能启动 P2 部分。**

### 中性

- 需要一个链下索引器（订阅区块 → 建视图）来支撑海图查询。纯读服务，不影响信任模型。

## 5. 复核触发条件

以下任一发生时，本 ADR 必须重新评审：

- 对齐假设 A-01 / A-02 / A-03 / A-05 / A-10 中任一被策划推翻
- `islands.json` 日产字段补齐后，发现日产依赖玩家侧变量（A-07 被推翻）
- 知识缺口 G-03（单 transition 可消费 record 数上限）实测结果无法支撑 5 卡编队
