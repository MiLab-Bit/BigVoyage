## 1. 三条必须先读的结论

**① `$TIDE` 不该由护岛日产铸造，改为赛季奖励池划拨。**
D5 要求 `net_issuance ≤ 0`。若日产 mint `$TIDE`，则必须靠 burn 去凑守恒——工程已指出这会导致"burn 不足时 claim 交易 revert"，玩家点了领取按钮却失败，是体验灾难。改为**从预铸的赛季奖励池划转**后，`net_issuance ≤ 0` 变成**结构性恒成立**，不依赖任何运行时条件。Demo 预置 5,000 枚，单人 30 日累计领取 228 枚（4.56%）。

**② D5 的「通胀率 ≤5%/天」在当前定义下是不可验收的。**
断言原文没有定义分母。滚动口径（分母=前日池存）下实测峰值 4.73%，固定口径（分母=初始池 50,000）下 0.14%——**差 33 倍，两个都能说自己 PASS**。更严重的是：滚动口径下结果**随玩家投入率在 0.98% ~ 14.49% 之间摆动**，纯囤积玩家必 FAIL 且**任何 sink 都救不回来**（维护费 ×6 无效、囤积衰减 ×6 无效）。→ 必须锁定「口径 + 参考玩家档案」二者，见 §5.3。

**③ 卡牌养成轴不是可选项，它是 Demo 唯一有容量的 sink。**
Demo 四类 sink 中，造船 24,000 一次性、岛屿开发 300,000 一次性、维护费仅约 1,250/日。**只有养成轴（345,600）单独占了总 sink 容量的 49%**，且它同时是 GDD-03 §6.5 B3（Boss 不可达）的唯一解法方向。**砍掉养成轴 = 同时砍掉经济闭环和进度曲线。**

### 3.4 护岛日产（第二 faucet，占 14~20%）

完整公式、每岛 `ISLAND_M` 终配表、世界观换算依据见 **`GDD-04 §6.1`**。此处只放摘要与链上关键点：

```
yield_i = 120 × ISLAND_M[i] × (1 + 0.25·dev_i) × (1 + 0.25·adj_owned_i) × DECAY(k)
```

| 输入 | 链上可读？ | 来源 |
|---|---|---|
| `120`（`ISLAND_DAILY_YIELD`） | ✅ 电路常量 | `constants.json` 冻结 |
| `ISLAND_M[i]` | ✅ 静态表，可硬编码进程序 | **本文补，见 `data-spec/`** |
| `dev_i` | ✅ `mapping u8 => u8` | 链上状态 |
| `adj_owned_i` | ✅ 由 `owner mapping` + 静态邻接表推出 | 链上状态 + 常量 |
| `DECAY(k)` | ✅ `k` = 该玩家占领序号，`mapping (address,u8) => u8` | 链上状态 |

**五项输入全部链上可读 → 护岛日产可以做成链上纯函数** ✅ 这是对工程 **A-07** 的正式回应，详见 §8。

| | | **一次性合计** | **669,600** | | |

> **⭐ `refit` 是本文新增的关键 sink**。理由与实测见 §5.2 —— 没有它，D5 在"玩家全额投入"时反而 FAIL。

### 4.2 养成公式（与 SSOT 一致）

> **【已决 · D2】** 主理人已拍板 `LVL_STEP = 0.05`。本节口径**即为终值**，`11 号文 §4` 的 0.02 已同步覆盖，C-3 关闭。

```
stat(L, asc) = min(STAT_CAP, base × (1 + LVL_STEP·(L−1)) × (1 + ASC_STEP·asc))
LVL_STEP = 0.05     [无量纲/级]     ← 已决终值（GDD-03 §6.5 方案 1）
ASC_STEP = 0.08     [无量纲/突破]
STAT_CAP = { atk:200, def:200 }    hp 无 cap
综合养成倍率 gm(L) = 1 + 0.05·(L−1)  →  gm(1)=1.00  gm(5)=1.20  gm(10)=1.45
```

> ✅ **C-3 已闭合**：11 号文原用 `LVL_STEP = 0.02`（`gm(10)=1.18`），**已按裁决改为 0.05**。依据：`verify7.py` 实测 `gm=1.18` 时 FR_09 全收集胜率仅约 5%、进度曲线断裂；`gm=1.45` 时到 37.6%。**养成轴要能解 B3，斜率就必须是 0.05 量级。**
>
> **复跑确认（`bv_cascade.py`，2026-08-02）**：0.05 斜率下 FR_12（渊眼 Boss）胜率随等级 **Lv1 ≈3.9% → Lv5(gm1.20) ≈7% → Lv10(gm1.45) ≈29~30%**，养成轴成为 Boss 岛的有效解题路径，单调爬升无反转 ✅。

### 4.3 容量比与内容耗尽

```
30 日累计产出（参考玩家）≈ 210,000 资源点（POI 156,000 + 护岛 22,000 + 首占 88,000 的部分）
一次性 sink 总容量        = 669,600
容量比 = 669,600 / 210,000 = 3.19  ✅ 充裕
```

但**容量充裕 ≠ 曲线平滑**：实测第 25 日造船 sink 投满，当日总投入从 5,595 掉到 3,524（−37%），日通胀立刻从 0.55% 跳到 3.88%。**sink 的问题从来不是总量，是"任一时刻是否有可投入的去处"**——这正是 `refit` 存在的意义。

→ **新开 P0-3′ / `COMPILATION-REPORT §9` 的 D13**，须与 `DEF_COEF` **同批**冻结。

### 6.5 H-2 / H-7 与边界

- **H-2（UR 溢价 4.93×）**：这是**商业风险**而非玩法 bug。对要卖 NFT 的链游，UR 强是卖点；但 4.93× 意味着无 UR 玩家在 PvP 裁决战里基本没有胜算。缓解手段已内建：裁决战 `DUEL_COST ≤ 6` 使"3 张 UR = COST 12 > 6"**无法直接搬主线最强三卡**（`GDD-03 §6.6`）。**建议保留 4.93×，但把裁决战列为 Must**——它是唯一能让无 UR 玩家有获胜可能的场景。
- **H-7（养成轴）**：Lv10（`gm=1.45`）能救 FR_06（59.1%）与 FR_09（37.6%），**救不了 FR_12（恒 0%）**。FR_12 必须降规格，方案见 §9 与 `GDD-03 §6.5`。
- **养成撞顶边界**：`IRON_UR_01` def=170，`gm(10)=1.45` → 246.5 > `STAT_CAP.def=200`。**该卡从 Lv7 起 def 不再增长**（170×1.176=200），玩家会看到"升级了但属性没涨"。UI 必须显式提示"已达上限"，否则是明确的体验 bug。同类情况还有 `IRON_SSR_01`（115 → Lv10 166.75，未撞顶，安全）。

## 7. 链上确权资产清单——哪些数值影响链上确权

> 这是 team-lead 明确要求单列的一节。判定原则：**一个数值上链，当且仅当它满足「可转让 / 或 需被第三方独立重算」**。
> 只是"要防作弊"不构成上链理由——防作弊靠服务端权威即可，上链的成本是不可逆的 record 结构锁定。

### 7.1 上链资产与其数值依赖

| 资产 | 链上形态 | **锁定的数值** | 位宽依据 | 一旦上链后改这个数值的代价 |
|---|---|---|---|---|
| **船员卡 `crew_card`** | `record Crew` | `card_id`(u16) · `atk`(u16) · `def`(u16) · `spd`(u16) · `hp`(u32) · `cost`(u8) · `system`(u8) · `rarity`(u8) · `level`(u8) | `STAT_CAP={200,200}` → u16 足够 | 🔴 **极高**。已铸 record 需迁移；平衡性调整会让链上卡与链下卡语义分叉（A-03 / A-11） |
| **船图纸 `ship_blueprint`** | `record Blueprint` | `ship_id`(u8) · `armor`(u16) · `capacity`(u8) · `atkMod`/`defMod`(u16 定点) | `ships.json` 三船 | 中 |
| **岛屿主权** | `mapping u8 => address` | `island_id`(u8, 0~35) · `tier`(u8) | 岛屿总量 36 硬上限（A-10） | 高（改岛数需改 mapping 语义） |
| **护岛日产 claim** | `transition claim_island_yield` | `ISLAND_DAILY_YIELD=120` · `ISLAND_M[i]` · `DEV_STEP=0.25` · `ADJ_BONUS=0.25` · `DECAY 斜率=0.06` · `MAX_CLAIM_DAYS=30` | 全部静态/链上可读 | 中（可通过程序升级换公式，但历史 claim 不可追溯重算） |
| **`$TIDE`** | Aleo token program | `TIDE_BY_TIER={0,1,3,8}` · 赛季池预铸总量 5,000 | — | 中 |
| **战报承诺** | `field`（Poseidon 哈希） | `ruleset_hash`（含 `RESTRAINT` / `TYPE_COEF` / `SEG_DECAY` / `ARMOR_CAP` / `STAT_CAP` 全部战斗常量） | 全宽，禁截断 | 🔴 **改任一战斗常量 = `ruleset_hash` 变化 = 旧战报无法验证** |
| **占岛时间戳** | `mapping (address,u8) => u32` | `last_claim_height` · 占领序号 `k`（供 `DECAY(k)`） | `BLOCKS_PER_DAY` | 低 |

### 7.2 明确**不**上链（链下服务端权威）

| 项 | 为什么不上链 |
|---|---|
| `strategic` 资源池 | 单池软通货，不可转让，无第三方重算需求（A-08） |
| `stamina` 体力 | 日刷清空，是节奏阀门不是资产 |
| POI 探索记录 / 掉落 roll | 上链即暴露掉率种子；且是高频写入，gas 不可接受 |
| `dev_i` 之外的建筑/科技进度 | Demo 不实装 |
| 舰装 gear | 按 A-05 保持链下附属 |
| 琥珀币 | 法币充值币，合规上不宜上链 |

### 7.3 🔴 三条"数值—链上"耦合红线

1. **`ruleset_hash` 把全部战斗常量焊死。** §6.3 的 `SEG_DECAY` 0.60→0.40 与 §6.4 的护甲公式，**都会改变 `ruleset_hash`**。→ **必须在链上电路冻结之前完成**，否则代价从"改一行配置"变成"旧战报全部失效"。**这是本文对排期的唯一硬性要求。**
   > **状态（2026-08-02）**：两项均已拍板落库 —— `SEG_DECAY = 0.40`（D3）、`DEF_COEF = 0.30`（护甲方案1，减法模型保留；**非**除法）。
   > **✅ 冻结前置已归零（2026-08-02）**：P0-3「DoT 是否纳入护甲通道」已裁决为 **② DoT 也过减法扣甲**（D13②），FR_12 回落 16.71%→11.96% 落回 5~15% 区间。全部战斗常量定值，`ruleset_hash` 可冻。详见 `design/data-spec/RULESET_LOCK.md`。

   **`ruleset_hash` 战斗常量清单（冻结用，2026-08-02 终配）**：

   | 常量 | 终值 | 出处 | 状态 |
   |---|---|---|---|
   | `SEG_DECAY` | **0.40** | D3 / §6.3 | ✅ 已决 |
   | `ARMOR_CAP` | **0.80** | C-5 / FR_12=A | ✅ 已决 |
   | `STAT_CAP` | **200**（atk/def 各） | A-03 | ✅ 已决 |
   | `DEF_COEF` | **0.30** | ★护甲方案1 / §6.4 | ✅ 已决 |
   | `LVL_STEP` | **0.05** | D2 / §4.2 | ✅ 已决 |
   | `DoT 护甲通道` | **`max(1, round(baseAtk×dotRate×restraint − target.def×DEF_COEF))`** | D13② / §6.4.1 | ✅ **已决（2026-08-02）**：DoT 过减法扣甲，FR_12 16.71%→11.96% 落回区间；冻结前置归零 |

   > 另：`RESTRAINT`(1.3) / `TYPE_COEF` 表 / `env` 表 / `GUARD_MAX_ROUND`(30) / `MAX_EXTRA_HIT`(2) /
   > `MAX_DOT_STACK`(5) / `MAX_STUN_ROUND`(3) / `MAX_SHIELD_MULT`(2.0) 一并进 `ruleset_hash`（口径未变，见 §7.1）。
   > `guards` 数据（含 ★Q5 `FR_09.hp_mult = 1.20`）**不在常量清单内**，但属 ruleset 数据快照，改值同样影响旧战报可复算性。
2. **`STAT_CAP` 决定字段位宽（A-03）。** 一旦按 `{200,200}` 定死 u16，未来赛季数值膨胀就需要 record 迁移。→ 建议**位宽直接留到 u32**，成本是每张卡多几个字节，收益是避免一次不可能完成的迁移。
3. **护岛日产公式的每一个输入都必须是链上可读的静态量或链上状态。** 本文 §3.4 已逐项核对通过。**未来若有人想加"驻防编队加成""皮肤加成"，闸门 C 立刻失效**——请在 `data-spec/` 与 ADR-002 双向标注此约束。

## 8. 链上对齐待确认项：A-01 ~ A-12 策划侧逐条裁决

> 来源：`architecture/asset-ownership-boundary.md §4`（工程 BV-Eng 提出的 12 条对齐假设）。
> 裁决口径：**✅ 确认**（假设成立，工程可据此实施）/ **⚠ 有条件确认**（成立但附加约束）/ **❌ 推翻**（假设不成立，需改方案）。

### A-01 · 链上裁决战可降规格（3v3 / 8 回合）— **✅ 确认**

**裁决**：确认，且策划**主动要求**降规格——不只是为了电路约束，更是为了玩法。

```
DUEL_SLOTS = 3 · DUEL_CAPACITY(COST) ≤ 6 · DUEL_MAX_ROUND = 8 · DUEL_SAME_SYS_CAP = 2 · MAX_EXTRA_HIT = 1
```

`verify.py` 实测：合法编队 **740 种**（3 槽满编 552 种），TTK 中位 **6.5 回合**，**63% 在 8 回合内自然分胜负**，其余按剩余 HP% 判（平局归守方）。
**`COST ≤ 6` 是关键设计点**：3 张 UR = COST 12 > 6，玩家**无法直接搬主线最强三卡**，裁决战自带独立 meta。这同时是 §6.5 里缓解"UR 溢价 4.93×"的唯一手段。
**风险**：这是一个**新玩法模式**，需要新 UI（编队页 + 对战页 + 结算页）。范围分层建议 **Should**（比赛核心 zk 亮点，但若排期紧张可用"演示模式"代替完整玩法）。

### A-02 · 定点化偏差可接受 — **✅ 确认**

**裁决**：确认。**以定点版为唯一真源，浮点版下线**，不做双版本并存。
理由：并存必然分叉，分叉后"哪个是对的"无法回答。既然 Leo 无浮点是硬约束，就让定点版成为唯一真源，重跑一次平衡即可。
**附加要求**：定点化落地时必须**重跑本文 §6 全部审计与 GDD-02/03 的进度曲线**，因为 `SEG_DECAY^k` 的连乘在定点下会累积舍入误差（4 段疾风连乘 3 次）。建议 `SCALE = 10000` 且**段衰减用查表而非连乘**（`[10000, 6000, 3600, 2160]` 预计算），可完全消除累积误差且省电路约束。

### A-03 · `STAT_CAP={200,200}` / `BOSS_HP=5000` 是永久上限 — **⚠ 有条件确认**

**裁决**：`STAT_CAP` 在**基础卡面值**上确认；但**养成后的有效值会撞顶**（§6.5：`IRON_UR_01` def 170 × `gm(10)=1.45` = 246.5）。
→ 工程需明确：链上 record 存的是**卡面基础值**还是**养成后有效值**？
  - 存基础值 → u16 安全，但链上无法独立算战力（需要 level 也上链，本文 §7.1 已列入）
  - 存有效值 → **必须留 u32**
**建议：存基础值 + level，位宽仍取 u32。** 多几个字节换掉一次不可能完成的迁移，是划算的。
`BOSS_HP = 5000` **❌ 部分推翻**：见 A-12 下方的 B3 说明，该值在当前卡池下不可达，策划已请求下调。

### A-04 · `seed` 不影响战斗结果是可接受设计 — **✅ 确认**

**裁决**：确认，且这是**正面设计**，不是妥协。支柱 1「一切可计算」要求玩家能在出战前算出结果；引入随机会直接摧毁这条支柱。
**但必须修 UI**：当前保留 `seed` 入参却不使用，玩家/评审会误以为有随机。→ 要么在战斗结算页写明「本作战斗无随机数，同编队必然同结果」，要么把 `seed` 从玩家可见层移除。**"看起来有随机但其实没有"是最坏的一种。**

### A-05 · 舰装 gear 不作为独立链上资产 — **✅ 确认**

**裁决**：确认。Demo 根本不实装 gear（`GEAR_STAT_CAP=0.10` 是全量愿景）。P1+ 若要做，也建议保持链下——gear 上链会让编队合法性电路必须同时验证"卡归属 + 装备归属 + 装备关系"，约束翻倍，收益只是"gear 可交易"这个次要需求。

### A-06 · 日产按每日 1 次 claim 结算 — **✅ 确认**

**裁决**：确认，且"离线累积、上线领取"是**正面体验**（给回归玩家一个开箱时刻）。
**附加规格**：`MAX_CLAIM_DAYS = 30` 截断（防溢出 + 防"挂机一年一次性倾泻"砸崩经济）；UI 显示"未领取 N 天，即将达上限"警告。
**边界**：`DECAY(k)` 中的 `k` 是占领序号，离线期间不变化，因此补算是安全的（`GDD-04 E1`）。

### A-07 · 岛屿日产为 `f(tier)` 纯函数、无玩家侧变量 — **⚠ 有条件确认（原"数据缺口"判断需更正）**

**先更正一个事实**：`islands.json` 确实没有日产字段，但**设计源是存在的**——`docs/design` 分支 `世界观叙事/世界观圣经（完整版）.md §4.1` 已为 36 岛逐岛定义了「专精产出 +N/天」（G1 霜牙岛 寒铁 +10/天 …）。**这不是"数据缺失"，是"设计资产未迁移到数据层"。**

**裁决**：假设**基本成立但需要放宽**。日产不是 `f(tier)` 的纯函数，而是：

```
yield_i = f(ISLAND_M[i], dev_i, adj_owned_i, k)
```

四项输入**全部链上可读**（静态表 / mapping / owner mapping 推导 / 占领序号），因此**链上纯函数性成立** ✅，但工程需要三项额外支持：

| 需新增 | 形态 | 说明 |
|---|---|---|
| `ISLAND_M[i]` | 电路内静态表（12 项 u16 定点） | 见 `data-spec/islands.patch.json` |
| `dev` | `mapping u8 => u8` | 岛屿开发度 |
| 占领序号 `k` | `mapping (address,u8) => u8` | 供 `DECAY(k)` |

**换算依据**（让冻结常量 120 有世界观来源，而不是魔数）：
```
ISLAND_M[i] = 特产数量_i × RESOURCE_VALUE[种类] / 120
RESOURCE_VALUE = { 寒铁:12, 鲸脂:12, 珍珠:12, 冰晶:20, 古老铭文:60 }
校验：G1 霜牙岛 10 × 12 = 120 = ISLAND_DAILY_YIELD  ✅
```

**给 ADR-002 的硬约束**：未来任何"驻防编队加成 / 建筑等级 / 皮肤加成（`RESOURCE_SKIN_CAP_BONUS=0.30`）"进入日产公式，**闸门 C 立刻失效**。请在 `islands.json` 与 ADR-002 双向标注。

### A-08 · `strategic` 不上链，只有兑换成 `$TIDE` 的部分上链 — **⚠ 有条件确认（兑换口 Demo 不开）**

**裁决**：`strategic` 不上链 ✅ 确认。
**但 Demo 内不应开放 `strategic → $TIDE` 兑换口**。理由：兑换口一开，`$TIDE` 的发行量就与链下资源池挂钩，`net_issuance ≤ 0` 就得靠 burn 去凑（工程已指出 revert 风险）。**Demo 的 `$TIDE` 只走"赛季奖励池划拨"这一条路**（`GDD-04 §6.8`），守恒是结构性的。
`SOFT_TO_HARD_RATE=150` / `SOFT_EXCHANGE_DAILY_CAP=3` 这两个冻结常量在 Demo **不激活**，留给 P1+。

### A-09 · 日限以区块高度为时间源，与自然日 0 点有偏移 — **✅ 确认**

**裁决**：确认。**以链上日为唯一真源**。
**UI 强制要求**：所有日限/日刷相关展示一律用「距下次刷新：约 N 区块 / ≈M 小时」，**不显示"今晚 24:00"这类自然时间**。否则玩家按手机时间等到 0 点却领不到，会被判定为 bug。
体力 `daily_00_clear` 在 Demo 单机下仍走本地日，**但一旦接链必须切到链上日**，两套刷新时间不可并存。

### A-10 · 36 岛硬上限、每岛唯一归属 → 多数玩家占不到岛 — **❌ 推翻（这是真问题，需玩法解）**

**裁决**：**假设本身技术上成立，但它揭示的玩法风险必须由策划解决，不能带进多人化。**

| 场景 | 岛/人 | 护岛经济对多少人有效 |
|---|---|---|
| Demo 单人 | 12 / 1 | 100% |
| 100 人同服 | 36 / 100 | **≤36%** |
| 1000 人同服 | 36 / 1000 | **≤3.6%** |

**策划侧三个解法（P1+ 决策，Demo 不阻塞）**：

| # | 解法 | 说明 | 对链上结构的影响 |
|---|---|---|---|
| 1 | **联盟共治**（世界观已支持） | 世界观圣经 §7.1 写的就是"占领岛屿的**联盟**成为护岛者"——**单人独占本来就不是原设定**。改 `mapping u8 => address` 为 `mapping u8 => alliance_id` | 中等，需新增联盟程序 |
| 2 | **分服/分片** | 每 36 人一个海域实例 | 大（岛 ID 需加 shard 维度） |
| 3 | **岛屿分层**：核心岛唯一归属 + 外围"驻点"可多人共存 | 保留稀缺感，同时让散人有产出 | 大 |

> **本人推荐解法 1**。它不是新设计，而是**回到世界观原设定**——现在的"单人占岛"才是 Demo 简化带来的偏离。`asset-ownership-boundary.md` 把它记为"玩法风险"是准确的，本文正式认领这个风险，并把它列入 P1 的 Must。

### A-11 · 卡 ID 可稳定映射 u16 且卡池只增不改 — **⚠ 有条件确认（本文 §6 就在要求改）**

**裁决**：`card_id → u16` ✅ 确认（20 张 → 全量数百张，u16 绰绰有余）。
**"只增不改"❌ 无法承诺**：本文 §6.2 的 H-2/H-3/H-4/H-5 四条平衡假设**当前都不达标**，平衡性调整是必然的。
**但可以给一个更强的承诺**，请工程按此设计：

```
承诺 1：card_id / system / rarity / cost   —— 永不改（这四项进 record，是身份）
承诺 2：atk / def / spd / hp               —— 可改（不进 record，链上按 card_id 查静态表）
承诺 3：静态表版本化 stat_table_version    —— 进 ruleset_hash，旧战报用旧表验证
```

这样平衡性调整不会让已铸 record 语义漂移，也不会让历史战报失效。**这是本文对 A-11 的反提案，建议工程采纳。**

### A-12 · 代码行为优先于 `数据层/constants.md`，电路不实现未实装的三项 — **✅ 确认**

**裁决**：确认。`MAX_STUN_ROUND` / `MAX_SHIELD_MULT` / `TRUE_DMG_*` 在 Demo **不实装**，电路不实现。
**但策划侧要求把它们从 Demo 的 `constants` 有效集中移出**（标记 `PHASE: P1+`），而不是留在表里当"已冻结但没用"的僵尸常量——这正是本次两个 agent 都踩坑的原因：`数据层/constants.md` 里躺着一堆无法区分"已实装 / 待实装 / 已废弃"的值。
**这是文档治理问题，成本极低，收益是后续所有 agent 不再误读。**

### 9.3 🔵 H-6 满编激励候选方案（2026-08-06，待复跑验证 · 登记册 [B6] 设计输入）

> **定位**：本小节为**设计假设**，方向已由用户拍板 = **编队规模加成 + 体系链奖励组合**；经 engineering-lead 复跑验证后才生效，生效前下游文档不得断言 H-6 已咬住。
> **红线自检**：不触碰任何 RULESET_LOCK 冻结常量（`SEG_DECAY=0.40` / `ARMOR_CAP=0.80` / `STAT_CAP={200,200}` / `DEF_COEF=0.30` / `LVL_STEP=0.05` / `RESTRAINT=1.3` / `FLEET_SLOTS=5` / `FLEET_CAPACITY=10` / `SAME_SYS_SOFT_CAP=4` / `COST_BY_RARITY` 等）；不新增体系；不破克制环；所有加成 ≤20%（§12.5 红线 2）。全部新增量为**战斗期 atkMod 乘区**（`PLAYTEST_KNOB`），非基础属性、非冻结值，不触发 `ruleset_hash` / `econ_ruleset_hash` 重冻。

**现状回顾（H-6 问题）**：现状最优解 = 2~3 张堆最高费卡（2 UR + 1 SR ≈ COST 10），三约束里只有 COST 咬住，槽位与同体系上限形同虚设，编队构筑退化为"堆最高费卡"，动摇「构筑即核心系统」支柱（对应登记册 [B6] 待裁决）。本方案目标：用数值让「张数」与「体系纯度」重新成为有竞争力的构筑维度。

#### 9.3.1 方案 A · 编队规模加成（Fleet Size Bonus）

| 上阵张数 n | 全队 atkMod 加成 | 说明 |
|---|---|---|
| 1~2 | **+0%** | 不奖励小编队 |
| 3 | **+4%** | 与 2 张拉开可感知差距 |
| 4 | **+8%** | |
| 5 | **+12%** | 满编收益最高 |

- **通道**：战斗期 atkMod 乘区，与既有 buff 通道（如 `FLAME_SR_01` +15% atk）同乘区加算；`eff_atk' = eff_atk × (1 + fleet_size_bonus)`。单位：无量纲。
- **为什么梯度让 5 张满编在数值上反转占优（一阶论证）**：
  1. **乘区差**：小编队 3 张吃 +4%，满编 5 张吃 +12% → 满编相对小编队多 `1.12/1.04 − 1 ≈ +7.7%` 的团队输出乘区增益；
  2. **张数战术价值（未计入 atkMod）**：5 单位 vs 3 单位，每回合主动次数 5 vs 3、总 HP 池更大（续航）、减员损失分散、DoT/盾/控制覆盖更广；
  3. **DEF_COEF=0.30 后的低费保值（§6.4.1）**：R 卡跨靶保值率 `0.071 → 0.433`，5 张满编里可塞的 R/SR 不再是白板，0.30 口径下 `FLAME_R_01` 对重甲靶 DPR/费 `0.7 → 12.0`；
  4. 三者叠加 → 满编 5 张在**胜率维度**应反转占优。⚠ 诚实说明：单看 atk 加和小编队（UR+UR+SR ≈ 439 有效 atk × 1.04）仍略高于 5 张满编（≈ 425 × 1.16），**反转依赖张数价值与组合效果**——精确幅度由复跑判定（见 9.3.4 指标 ①），梯度列敏感性参数。

#### 9.3.2 方案 B · 体系链奖励（System Chain Bonus）

| 同体系张数 | 本体系卡 atkMod 加成 | 说明 |
|---|---|---|
| 1~2 | **+0%** | — |
| 3 | **+4%** | 解锁体系链 |
| 4 | **+6%** | 软上限内最高档 |

- **触发**：编队内同体系 ≥3 张时，该体系全部卡获得加成；4 张同体系为最高档。**天然封顶**：`SAME_SYS_SOFT_CAP=4` 禁止 5 张同体系（`≤4`），链奖励无需额外上限。
- **通道**：与规模加成同乘区加算——本体系卡 `×(1 + size + chain)`，异体系卡 `×(1 + size)`。
- **设计意图**：在软上限 4 内鼓励「3~4 张同体系 + 1~2 张针对性异体系」的构筑——既凑链吃加成，又保留克制环留位（1 张异体系用于打天敌），不逼单一体系、不破坏四体系克制环主导。

1. **UR 基础值碾压**——2 UR 基础输出远超 5 张 SR/R 组合，编队收益被 UR 基础值主导，等比 atkMod 加成填不平；
2. **等比加成不改变张数构成**——加成为等比乘区，胜方仍是"2 UR"，张数构成不因激励移动；
3. **纯度换克制留位净亏**——凑同体系链失去克制灵活性（可放克制位），净亏。

**调参红线**：链档 ≤6%（8% 破环）；规模 15% 与链 6% 不可同开（破 ⑦ 上限）。

**状态**：🔴 方案**不生效**，H-6 维持「设计意图/软约束，待裁决」。需**结构性重定标**（满编专属强档 + 链机制重设计——如改机制/技能触发而非纯 atk + 对照域修订），或**重新审视 H-6 假设本身**（"上满 5 张"是否仍是正确支柱，或核心构筑应转向「COST 分配 + UR 选择」深度）——二者均待主理人/用户拍板。

#### 9.4.2 满编专属强档：舰队共鸣层（回应根因 1+2）

> **触发规则（硬门，非梯度）**：出战 = **5 张**（`FLEET_SLOTS` 打满）→ 解锁「舰队共鸣层」。n ≤ 4 **结构性拿不到**（不是少拿一点，是拿不到）——这是"质变"与 v1"量变"的分界线。

**R1 · 合击段（Combo Strike）**

```
触发：每回合，舰队第 5 个行动的存活单位（压轴位）行动后，对当前目标追加 1 段合击。
伤害 = COMBO_COEF × Σ_{i ∈ 存活} [ pierced_atk_i × restraint(sys_i, tgt) × typeCoef(dtype(sys_i), tgt.armor) × (1 − armor_ratio_tgt) ]
      pierced_atk_i = max(1, eff_atk_i − tgt.def × DEF_COEF)      [atk 点，走既有 ② 减法扣甲]
      restraint(sys_i, tgt)  = 克制 ×1.3 | 被克 ×1/1.3 | 无关 1.0   [无量纲，走既有克制通道]
COMBO_COEF = 0.35                                                [无量纲，PLAYTEST_KNOB，敏感性 0.35→0.45]
单位：HP 点（与 §4.3 单段伤害同量纲）；对单目标每回合最多 1 段合击。
上限：舰队级共鸣追加段每回合 ≤ MAX_EXTRA_HIT = 2（默认 1，敏感性可调 2；不修改冻结值，仅以其为 ceiling）。
```

- **为什么小编队结构性拿不到**：合击段定义在"第 5 个行动位"上，n < 5 时不存在该语义，不存在"折价版合击"——n=4 连 0.1× 的合击都没有。
- **为什么它让满编在"功能上"反转（一阶论证）**：
  1. **张数杠杆**：合击段随存活张数线性放大（5 张存活时全队输出池最大），张数越多收益越高 → 同池内"上满 5 张"结构性占优；
  2. **减员补偿**：R1 是全队合击，不依赖单卡存活时长，恰好补偿"5 张脆皮易被逐个击破"的生存弱点——即使剩 3 张存活，合击段仍按 3 张输出池结算，张数劣势被平滑；
  3. **机制独占**：n<5 拿不到，是"质变"而非"少拿一点"，直接回应根因 ②"改变最优解结构"。

**R2 · 共鸣技（Echo Skill，确定性联动）**

```
触发：满编时，每回合**首次**有单位释放技能（dot / armor / shield / control / buff / multi 任一）后，
      该技能对当前目标"共鸣"再结算一次（同回合只触发 1 次；无技能回合不触发）。
各技能共鸣效果（均受既有冻结上限约束）：
  dot     → 目标 DoT 层数 +1（≤ MAX_DOT_STACK = 5）
  control → 控制判定再 roll 一次（prob 不变，受 MAX_STUN_ROUND = 3 累计上限）
  shield  → 护盾量追加一次（≤ MAX_SHIELD_MULT = 2.0）
  multi   → 再打 1 段（≤ 单位 base_hits + MAX_EXTRA_HIT = 2）
  armor / buff → 效果对同体系另一名存活单位同步生效（无同体系则跳过）
```

- **定位**：R2 是"全队技能触发/联动"的落地形态（任务允许的方向二），与 R1 的"combo 段"互补——R1 保证每回合保底全队输出，R2 让满编队的技能循环更密；二者均只对满编开放。
- **设计取舍**：R2 为**确定性**（非概率），避免新增随机源冲击支柱 1「一切可计算」；若复跑显示 R1 已足够反转，R2 可作敏感性开关关闭（见 §9.4.5 参数设计）。

#### 9.4.3 体系链机制化（回应根因 3）

> **触发与档位**：编队内同体系 **≥3 张** → 激活该体系链；**≥4 张** → 链强化档。**天然封顶**：`SAME_SYS_SOFT_CAP = 4` 禁止 5 张同体系（`≤4`），链最高档 = 4 张，无需新增额外上限（不碰冻结值）。
> **通道**：机制层（追加段 / 概率），**不再进 atk% 乘区**——这是与 v1 方案 B 的本质差异。

| 体系 | 链 3 张（激活档） | 链 4 张（强化档） | 机制类型 | 冻结上限约束 |
|---|---|---|---|---|
| 烈焰·连爆 | 火焰单位主动命中后，追加 1 次「爆燃段」（burn，伤害 = 本次命中的 **0.5×**，走克制/护甲/类型通道） | 爆燃段 0.5× → **0.75×** | combo 联动（确定性） | 单目标单回合爆燃 ≤1 次 |
| 铁壁·反击 | 铁壁单位受击后，对攻击者追加 1 次「反击段」（physical，伤害 = 该单位 eff_atk 的 **0.4×**，走护甲通道） | 反击 0.4× → **0.6×** | combo 联动（确定性） | 单单位单回合反击 ≤1 次 |
| 疾风·连击 | 疾风单位多段命中后，追加 1 段（伤害 = 本次末段 × **0.8×**） | 追加段 0.8× → **1.0×** | combo 联动（确定性） | 单位总段数 ≤ base_hits + `MAX_EXTRA_HIT`(2) |
| 潮汐·回响 | 潮汐单位控制技能触发概率 **+10pp**；护盾技能效果 **+10%** | 控制 prob **+20pp**；护盾 **+20%** | 技能触发概率提升（概率） | control 走既有 prob 通道；护盾 ≤ `MAX_SHIELD_MULT`(2.0) |

- **与 `SAME_SYS_SOFT_CAP=4` 的关系**：链最高档 = 4 张，软上限恰好是链的天然封顶；设计意图 = 鼓励「3~4 张同体系 + 1~2 张针对性异体系」——**既凑链吃机制，又保留克制留位**（第 5 张放克制天敌），不逼单一体系、不破四体系克制环。4 张链 + 1 张克制位的叠加是否越界，由复跑 ⑦ 校验（边界 E-H3）。
- **为什么链用"机制"而非 atk%**：v1 根因 ③ 的本质是"atk% 是线性的，凑链损失克制位（×1.3→×1.0）是线性的，两者可互相抵消且纯数值无法提供净收益"；机制层（追加段/概率）是非线性的——它给的是**单位回合外的新动作**（爆燃/反击/连击/回响），价值随体系内张数**平方级**放大（3 张互喂），是克制位损失（线性）追不上的。

**9.4.3.4 设计逻辑证明：「功能收益 > 失去克制位损失」**
```
失去克制位损失（一阶）：
  克制位 1 张 ×1.3 → 换同体系 ×1.0 → 该位输出 −23% 当量（1 − 1/1.3）
  占 5 张队约 1/5 权重 → 全队 ≈ −4.6% 当量
链收益（一阶，以烈焰链为例）：
  3 张火焰 ≈ 全队输出 60% 当量；连爆 = 每火焰单位命中后追加 0.5× 单次命中
  → 每火焰单位输出 ×1.5 → 3 火焰 = 60% → 90% 当量 → 全队 +30% 当量（保守折半计 +15%）
  → 链收益（+15~30% 当量）>> 克制位损失（−4.6% 当量）
结论：功能收益 > 数值损失，凑链不再是"净亏"；精确幅度由复跑 ③ 验证（链编队 vs 无链同池胜率差 ≥ +5pp）。
```

#### 9.4.4 对照域修订

**v1 对照为何不公平（先纠偏再改）**：
- v1 的"2 UR vs 5 张 SR/R"混入了**稀有度变量**——它同时测试"稀有度价值"与"张数价值"，两者不可分。UR 高价值是**设计意图**而非缺陷（§6.5：H-2 的 4.93× 溢价是商业卖点不是玩法 bug，靠裁决战 `DUEL_COST≤6` 缓解；§12.5：付费买更宽的路不买更高的墙），让 5 张 R/SR 打平 2 UR = 要求"数量完全对冲质量"，会抹掉 UR 的商业价值、推翻稀有度阶梯（H-1）。

#### 9.4.6 边界与诚实风险

- ✅ **不碰冻结常量**：全部新增为 `R()` 可选参数 / 战斗期机制层（`PLAYTEST_KNOB`），非基础属性、非冻结值，不触发双 hash 重冻；

- **边界情况（≥3 类）**：

- **诚实风险（哪些点可能仍失败）**：
  1. **概率机制 vs 支柱 1**：潮汐链用概率（control prob）。引擎已有确定性 LCG，同 seed 可复现，但"无实际随机数"的 A-04 现口径需重新声明——seed 从"仅进 hash"变为"结果输入"。若主理人不接受，潮汐链可改确定性回响（每 N 回合必触发）——列为敏感性分支。

  3. **GAA 烈焰 ≤82% 可能被链放大**：烈焰连爆/共鸣技会强化火焰输出 → 跨 12 守卫聚合若破 82%，链档/爆燃系数须下调（敏感性：爆燃 0.5→0.4、R2 关闭）。
